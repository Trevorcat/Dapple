# LLVM OpenMP runtime (libomp)

* Purpose: LibRaw's parallel demosaic (`DAPPLE_LIBRAW_OPENMP`, default ON, Apple platforms since round 6). Android links the NDK's `libomp.a` statically (`-static-openmp`); the Windows desktop tools load `libomp.dll` from the llvm-mingw toolchain (copied next to the executables).
* Licence: Apache License 2.0 with LLVM Exceptions (the LLVM project). The exception allows static linking into binaries without the Apache attribution of the object code; the app's licences screen should still list "LLVM OpenMP runtime, Apache-2.0 with LLVM exception".

* Apple (2026-11-13): LLVM 19.1.7 `openmp` sources (github.com/llvm/llvm-project, release tarball `openmp-19.1.7.src.tar.xz` + `cmake-19.1.7.src.tar.xz`), built static by `scripts/ios/build-libomp.sh` for macOS arm64, iOS device and iOS simulator (no OMPT / OMPD / hwloc, ~0.86 MB `libomp.a` each) and linked only into `libdapple` / `dapple.framework` (LibRaw is compiled with `-Xclang -fopenmp`; `core/src/omp_apple.cpp` starts the team). Same licence as above (Apache-2.0 with LLVM exception); the licences screen must list "LLVM OpenMP runtime, Apache-2.0 with LLVM exception". Static libomp is a private runtime of the app binary (no dynamic OpenMP library is shipped, no private API used), nothing in it conflicts with App Store rules.

* LibRaw patch (2026-11-14, `cmake/Dependencies.cmake`, option `DAPPLE_LIBRAW_LOCKPATCH`, default ON, all platforms that build LibRaw with OpenMP): at configure time every `#pragma omp critical[(name)]` in the LibRaw snapshot (memory manager `libraw_alloc.h`, `raw2image.cpp`, `fuji_compressed.cpp`, `crx.cpp`, `pana8.cpp`, ...) is replaced by a scoped `std::mutex` (`if (std::lock_guard<std::mutex> g(dapple_lr_mutex()); true)`). LibRaw is dual-licensed LGPL-2.1 / CDDL-1.0 and used under CDDL-1.0; CDDL file-level terms: the modified files (listed above) stay under CDDL-1.0 and the modification is published with the app's source / licence screen entry for LibRaw. The OpenMP parallel regions (Fuji strips, demosaics, CRX, Nikon HE) are untouched, so the Fuji unpack speed-up is kept.
