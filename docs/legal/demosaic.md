# Demosaic node (core/engine/nodes/demosaic, core/engine/shaders/demosaic_*)

Nothing in this node is copied or translated from another project's source. The licence analysis, per implementation:

| Part | What it is based on | Third-party code? | Licence of what we ship |
|---|---|---|---|
| Bayer demosaic (CPU `demosaic_cpu.cpp` `bayerTile`, GPU `demosaic_bayer.comp`) | The Hamilton-Adams gradient-corrected green interpolation (U.S. patent 5,629,734, filed 1995, expired 2015; the method is described in the paper "Adaptive color plane interpolation in single sensor color electronic camera", Hamilton and Adams, 1997) with gradient weighting of the two directions, and colour-difference chroma interpolation (the standard colour-ratio / colour-difference family: Pei and Tam 2003 for the colour-difference idea). Written from the published descriptions. | none | our own code (project licence) |
| X-Trans demosaic (`xtransTile`, `demosaic_xtrans.comp`) | Directional green through the nearest greens of the 6 x 6 pattern with inverse-square gradient weights, a Laplacian term, guide-weighted colour differences, a 3 x 3 median of the differences. The idea of "interpolate green directionally, then red / blue as colour differences" is Markesteijn's (2007, dcraw's `xtrans_interpolate`), but nothing of that implementation (its direction tables, homogeneity maps, LAB conversion, three passes) was read into or ported: this is a simpler, different algorithm. | none | our own code |
| RCD (ratio-corrected demosaicing, L. Sanz Rodriguez) | NOT implemented. The Bayer method above is a different one (gradient-weighted Hamilton-Adams). RCD exists only in GPL-3 projects (RawTherapee, darktable); we did not read or copy it. | none | n/a |
| LibRaw's demosaic (AHD, X-Trans 1 / 3 pass) | Not ported, not linked into the node. It stays the RGB path of `ImageDecoder::decode` (the oracle and the fallback) and the reference of the quality tables. | LibRaw, CDDL-1.0 (docs/legal/libraw.md), unchanged | unchanged |
| Black level folding, white balance multipliers, colour matrix (`core/src/decoders/libraw_mosaic.inc`) | Reproduces, from reading `adjust_bl`, `scale_colors`, `convert_to_rgb` of the LibRaw snapshot that is fetched by `cmake/Dependencies.cmake`, what LibRaw computes for `use_camera_wb`, `highlight = 0`, `output_color = 4`. The code is written afresh (different structure) but it encodes the same arithmetic, and it contains the 3 x 3 ProPhoto (D65) primaries table that LibRaw's `colorconst.cpp` publishes (a table of numbers from the ROMM RGB specification: `0.529317 0.330092 0.140588 / 0.098368 0.873465 0.028169 / 0.016879 0.117663 0.865457`). | arithmetic mirrored from CDDL-1.0 code, no code copied | the file is ours; if the lead counts mirrored arithmetic as a derived work, the file falls under CDDL-1.0 file-level terms (source of that one file stays available), which the project already accepts for LibRaw |
| Shaders | Single-source GLSL, the same arithmetic as the CPU functions. SPIR-V by glslc, ESSL / MSL by dapple_shaderc (SPIRV-Cross, Apache-2.0, build tool only). | none | our own code |

Evaluation data: the public CC0 sample files under `build/rawsamples` only (docs/engine/raw-compat.md). Contact sheets and crops in `build/demosaic/` come from those files and never leave `build/`.

If a Markesteijn-class implementation is wanted later (three passes, homogeneity maps), the clean-room route is the paper / description of the method, or LibRaw's `xtrans_demosaic.cpp` under CDDL-1.0 with the file-level obligations; the GPL implementations (RawTherapee, darktable) are out.
