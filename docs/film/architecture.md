# Spectral film engine - architecture

Scope: the spectral film pipeline (`core/include/dapple/film.h`, `core/src/film*.{h,cpp,inc}`): bake + point-wise run kernels
(sections 1, 3) and the spatial / stochastic effects (section 2).
Functional definition: `docs/film/spec/01-data-spectral-filming.md`, `02-print-scan.md`, `03-spatial-effects.md`.

```
linear ProPhoto RGB
  | A  exposure        3x3 (CAT16 + ProPhoto->XYZ), chromaticity -> tc, bicubic raw-LUT lookup, x brightness, x 2^EV
  |      ---- hook "exposure": camera diffusion, lens blur, halation, scatter (linear film exposure) ----
  | B  log             log10(max(e,0)+1e-10)  (polynomial log2, |err| < 1e-7)
  | C  develop         density curve lookup (gamma) -> DIR inhibitor q = Q d + q0
  |      ---- hook "inhibitor": DIR diffusion of q ----
  |    develop         x' = x - q ; pre-coupler curve lookup (gamma) -> developed density d
  |      ---- hook "density": grain ----
  | D  print + scan    ONE baked 3-D LUT (film density -> display sRGB): enlarger, paper, scan, CAT02,
  |                    CAM16-UCS gamut compression, sRGB OETF; tetrahedral interpolation
  |      ---- hook "scan": scanner blur, unsharp mask ----
display sRGB (encoded float)
```

## 1. Two layers

### Bake (parameter-only work, `FilmModel`, `film_model.cpp`)

Everything that does not depend on pixels is evaluated once, multithreaded (`ThreadPool`), into
`FilmTables` (plain float arrays). Measured on an i7-14700KF (28 threads):

| table | size | bake |
|---|---|---|
| raw-exposure LUT (194 x 194 x float4 incl. reflect padding): spectra x sensitivities x window x gamut compression, white-balanced | 602 KB | 2-4 ms, cached per (film, window, surface, input gamut, UV/IR filters) |
| density curves + pre-coupler curves (3 x 256 x float2 value/slope) and DIR matrix | 12 KB | 0.2 ms |
| enlarger filtration solve + exposure normaliser + preflash + black/white correction | scalars | 0.2-0.4 ms |
| film density -> display sRGB LUT, 33^3 x float4 (enlarger, paper, scan, CAT02, CAM16-UCS compression, OETF) | 575 KB | 9-10 ms |
| **total, cold** | | **~12 ms** (target 150) ; 10 ms when only the print side changed |

A parameter change re-bakes only if `bakeKey()` (a string of every non-spatial parameter, `film.cpp`)
differs; spatial-only changes (grain size, halation, ...) do not. `renderPixelDirect()` evaluates the same
model in double precision without any table except the raw LUT: it is the test oracle.

Own data (nothing from the reference's LUT files): the chromaticity -> spectrum table is generated by
`film_upsample.cpp` (minimum-norm Jakob-Hanika sigmoid-polynomial spectra, projected Gauss-Newton on the
2-D chromaticity constraint; 192 x 192 coefficient triples, 590 KB, ~1.7 s once, stored in the pack); the
raw LUT of a film is then `sum_l T(l) S_m(l) w(l)` per node. The neutral enlarger filtration is solved per
film/paper pair (Newton, 0.3 ms) instead of read from the reference's database.

### Run (`film_kernels_impl.inc`)

Pure kernels over `KView` (pointers + scalars to the tables). No allocation, `std::function`, virtual
call, exception or libm call in a pixel loop. Per pixel, in `pxExposure/pxLogE/pxCurves/pxQ/pxPrintScan`:

* exposure: 3x3 as three float4 FMAs; one division gives both `1-x` and `y/(1-x)`; Mitchell(1/3,1/3)
  weights as cubics; 4 x 4 taps as 16 float4 loads + 16 FMAs; (channel-in-lane float4 = one 128-bit
  register per texel, no gathers);
* log: exponent extraction + odd series, vectorised over the three channels, one vector division;
* curves: 3 x (clamp, floor, one 8-byte load, one FMA) per lookup, uniform grid so no search;
* LUT: tetrahedral interpolation (branch-free rank sort of the fractions, 4 float4 loads, 3 FMAs).

**SIMD.** The kernels are written once with clang vector extensions (`ext_vector_type(4)`: SSE/AVX on
x86-64, NEON on arm64; a scalar struct with the same operators elsewhere). `film_kernels_impl.inc` is
compiled twice (`film_kernels_base.cpp`; `film_kernels_avx2.cpp` with `-mavx2 -mfma`, x86-64 only) and
`selectKernels()` picks at runtime with `__builtin_cpu_supports`. Verified in the object code: the AVX2
object has 97 packed `vfmadd..ps` against 76 scalar ones (the scalar ones are index/weight arithmetic),
4 packed divisions; the arm64 object built with the NDK has 99 `fmla v.4s`, 49 `fmul v.4s`, 4 `fdiv v.4s`.
Highway was not used (no new dependency); the vector-extension layer is ~60 lines.

**Streaming.** `FilmSimulator::render` runs rows in parallel (`parallelFor`, persistent pool); inside a
row the five kernels run back to back over **256-pixel blocks** held in two 3 KB stack buffers (L1), i.e. the
point-wise stages are fused without any full-frame intermediate and the stage loops stay short enough for
the out-of-order core to overlap neighbouring pixels (the per-pixel-fused variant `KernelSet::fused` is
1.4x slower on the test machine). Working set per thread: tables (~1.2 MB, L2) + 6 KB.
`renderStaged()` runs the same kernels stage by stage for the per-stage timings of `dapple film-bench`.

**Kernel layout (what the "avx2" set buys).** The kernels are 4-lane *channel-in-lane*, one pixel per vector, not
wide SoA with 8 pixels per vector. The AVX2 object therefore mostly buys VEX encoding, FMA and the wider load
ports; the arithmetic is not 8 pixels wide, and the table gathers (curves, LUT corners) dominate the per-pixel cost.
At ~145 cycles/pixel single threaded this is already memory/latency bound rather than ALU bound, which is why it is
left as is. Processing 8 pixels per iteration (two pixels in a ymm register for the exposure matrix, `logE` and the
curve evaluation) is a possible next step, the table lookups would stay scalar gathers. The scalar `f4` fallback
struct (non-clang compilers) is never compiled in CI and therefore untested; clang is the only supported toolchain
(Android NDK, llvm-mingw, Apple clang). `vmax` is written as a per-lane ternary, which clang lowers to `maxps` on
x86-64 and `fmax` on arm64 in the shipped objects, but the language does not guarantee it.
`tetra()` (tetrahedral interpolation) deliberately duplicates `lut.cpp`: that one works on the develop pipeline's
RGB-ordered 17^3..65^3 LUTs in display space, this one on the film-density LUT with a shaped (log-encoded) input
domain, a float4 payload and a separately baked end value; the layouts differ, sharing the code would cost more
than the 25 lines.

Measured (i7-14700KF, 26 MP, no spatial effects): **65 ms** full frame (400 Mpx/s), 1600 px preview
**4.4 ms** with a cached bake; single thread 31 Mpx/s (~145 cycles/pixel).

### Deliberate deviations from the brief

* Intermediates are interleaved float3/float4 (channel in lane), not planar SoA: every expensive stage is a
  table lookup, which needs channels together; SoA would turn them into gathers (absent on NEON). There are
  no large intermediates in the default path, so fp16 storage is not needed there.
* "256 x 256 tiles + halo": the point-wise path needs no halo and streams row bands x 256-pixel blocks.
  Tiles with halos belong to the spatial stages (below).
* Only sRGB output and ProPhoto input are implemented (the spec allows other spaces; the tables would be
  re-baked per output space, `CmaxTable` is per output space).

## 2. Spatial and stochastic effects (spec 03)

Implemented in `film_spatial.{h,cpp}` (plan + Gaussian-mixture engine), `film_spatial_render.cpp` (driver),
`film_spatial_kernels.inc` (SIMD kernels, compiled per ISA next to the point-wise kernels). When no effect is
active (`--no-spatial`, or every strength zero) `render()` is still the fused block path of section 1; otherwise
it runs the spatial path below. `FilmSpatialHooks` remain for external experiments (a set hook takes the old
full-frame five-pass path).

```
in (interleaved ProPhoto)
  | P1   exposure kernel -> planar float32 planes E (3);  global max for the boost
  |      boost (global max)                                         spec 03 s4.1   (pass over E, only if boost_ev > 0)
  | M1   camera diffusion filter (x) lens blur  -> one Gaussian mixture per channel          s4.2, s4.3
  | M2   scatter (x) halation                      -> one Gaussian mixture per channel          s4.4
  |      (E2 = planar linear film exposure after all of the above)
  | P3   log10, density, inhibitor q (planar, 1/2 resolution when every width >= 3.2 px)      s5.1
  | M3   DIR diffusion of q: (1-w) G + w E_l  (mixture, no identity part)
  | T    ONE fused tile pass (256 x 64 + halo, thread-local L2-resident planes), per tile:
  |        develop (logE, x - q', pre-coupler curves) -> grain (per sub-layer, merged sampler) -> grain blur
  |        -> print+scan LUT -> decode to linear -> glare field -> scanner blur -> unsharp -> encode -> out    s5.2, s6.2, s6.3
  |   with the enlarger diffusion filter (s6.1) the tile pass is split at the print exposure:
  |        T1 develop+grain -> LUT1 (density -> log10 paper exposure) -> exp -> M4 mixture -> T2 (log, paper curves, LUT3, scan stage)
out (display sRGB)
```

**Gaussian-mixture engine** (`applyMixture`). Every blur of the exposure side is linear, so a chain of effects is
a convolution of mixtures `w0 delta + sum_k w_k G_sigma_k` (variances add; `mixConvolve`; components within 3 %
of each other merge). Exponentials use the spec's three-Gaussian surrogate (renormalised: the published weights
sum to 0.9999). Components with `sigma < 3 px` run as the reference's truncated FIR (`r = floor(3 sigma + .5)`);
wider ones run on a box-filtered half-resolution pyramid: level `k = floor(log2(sigma / 2))`, low-resolution
sigma compensated for the box variance `(4^k - 1) / 12`, FIR at that level (r = ceil(4 sigma)), cascaded
Catmull-Rom x2 upsampling back to the full frame. Cost per pixel is O(1) in the radius (halation sigma 11 px, DIR
tail 100 px and a Pro-Mist bloom of 2500 um all cost about the same). The full-resolution part of a mixture is one
tiled pass (256 x 64 + halo, source window reflect-padded once, all components of the level accumulated in an L2
accumulator, one write). Measured against an exact double-precision Gaussian (`tests/film_tests.cpp`): worst
0.2 - 0.35 % of the dynamic range at hard edges and a mean absolute error of 6e-4 - 3.4e-3 on a 0.25-mean test image for the wide components (`sigma >= 4`; the largest levels are the least accurate, ~1 % of the local mean, which is below the weight of those components in every effect; 
`sigma < 4` is the exact FIR). Reflect boundary (scipy `reflect`) at every level.

**Grain** (`grainRow`). Stateless: `pcg3d(x, y, stream)` (3 x 32-bit words per call), `stream = hash(seed, channel,
sub-layer)`, so the pattern depends on (seed, x, y, layer) only: tile- and thread-independent (tested bit-identical
across tile sizes), re-render stable, GPU-portable. Each sub-layer is the spec's scaled Poisson with the exact
moments (`E[g] = D`, `Var = Dmax D s / n`): inverse lookup of the sub-layer curve value from the total density
(1024-entry table), floor `f * density_min`, `n = A f / a_p`. Sampling: inversion (CDF walk) for `lambda < 4`,
Cornish-Fisher normal above (exact mean/variance, skewness `1/sqrt(lambda)`). When no dye-cloud blur is needed
(`sigma < 0.17 px`, the usual case at >= 4000 px) the three sub-layers are drawn **as one variate** with the exact
summed mean, variance and skewness from a density-indexed table whenever the expected particle count of the sum is
>= 4 (a third of the cost). Statistics are checked against the spec formulas (`testGrainStatistics`) and against the
reference renders (flat-patch RMS within 1 - 2 %). Micro-structure (pixel < 0.6 um) and the single-layer path are
implemented.

**Glare** is a stochastic field added to the XYZ in the reference. The baked LUT already contains its mean, so the
tile pass adds `(blurred log-normal field / 100 - baked mean) * white_rgb` to the linear RGB *after* the LUT
(before blur/unsharp). Exact unless the pixel is gamut-compressed (then off by < 3e-4 of white).

**Scanner stage** runs in linear light: the LUT output is decoded with a 4097-entry table (extended linearly outside
[0, 1]), blurred / unsharp-masked with halo-less tile arithmetic, encoded with a 4098-entry table. Halo of the tile =
unsharp radius + scanner blur radius + grain blur radius + dye-cloud radius (typically 4 px).

**Memory.** Three sets of three planes (E / E2 / spare) in a persistent `Arena` (chunks survive between renders,
so the first-touch page-fault cost is paid once), plus the pyramid scratch (released after every mixture): 36
bytes per pixel, ~0.95 GB at 26 MP. The tile pass has no full-frame intermediate. (A fp16 `E2` would halve the
largest buffer; not done, the cost is conversion, not capacity, on desktop.)

**Measured** (i7-14700KF, 28 threads, AVX2; `dapple film-bench`, median of runs, Portra 400 + Endura, all
effects on, grain/halation/DIR/glare/unsharp at the reference defaults):

| | |
|---|---|
| 26 MP, no spatial effects | 60 ms |
| 26 MP, **all effects** | **~280 - 330 ms** (exposure->planar 39, scatter+halation 49, DIR 47, tile pass 130 - 140) |
| 1600 px, all effects, cached bake | 18 - 19 ms (exposure 2.5, halation 4.5, DIR 5.6, tile 6.9) |
| 1600 px, spec preview mode (no grain / DIR diffusion / blurs) | 9 - 10 ms |
| each effect alone, 26 MP (adds to the 60 ms base) | scatter+halation +65, DIR +75, grain +75, glare +30, unsharp +30, Pro-Mist camera filter +75 |

Targets of the brief: 26 MP all effects <= 1.0 s (met, 0.3 s), 26 MP no spatial <= 0.3 s (0.06 s), 1600 px
preview <= 20 ms (met). Single thread, all effects, 26 MP: ~2.9 s (8.8 Mpx/s). The Android arm64 build (NDK 28, `-O3`)
compiles the same sources (NEON via autovectorisation of the block loops; no x86 intrinsics anywhere).

### Mapping to Vulkan compute / Metal

| stage | GPU form |
|---|---|
| exposure -> planar, boost | one dispatch (+ `max` via subgroup reduction + atomic) |
| mixtures | pyramid via `vkCmdBlitImage` / compute 2x2 box, separable FIR in workgroup shared memory (tile + halo, same 256 x 64), Catmull-Rom upsampling = 16-tap `texelFetch` or two bilinear taps; every level is a texture |
| grain | per-pixel compute: `pcg3d` is 32-bit integer math (identical on every GPU), tables = 1D textures; the sampler is branch-light (inversion only for `lambda < 4`) |
| tile pass | one dispatch per 256 x 64 tile with the halo in shared memory; LUT = 3D texture |
| DIR half-resolution field | `R32F` images at half size, sampled with a bicubic fetch in the tile pass |

## 3. GPU mapping of the point-wise stages (Vulkan compute on Android, Metal on iOS)

The run layer is already shaped as GPU kernels: each stage reads/writes pixels and a few read-only tables.

| CPU table | GPU resource | notes |
|---|---|---|
| `raw` (194 x 194 float4, reflect padded) | `RGBA32F` 2D texture, `clamp` addressing, point sampling | Mitchell weights in the shader (16 `texelFetch`), or pre-filter once and use hardware bilinear + Catmull-Rom 9-tap |
| `dn`, `d0` (3 x 256 x float2) | three `RG32F` 1D textures (or one 256 x 3 2D), linear sampling | value/slope pairs make `fma(f, slope, value)`; hardware linear filtering gives the same result with one fetch |
| `lut` (33^3 float4) | `RGBA16F` 3D texture (RGBA32F if accuracy matters) | hardware trilinear is the cheap option (use a larger N, e.g. 49, and measure dE against the CPU tetrahedral result) or emulate tetrahedral with 4 `texelFetch` |
| `mIn`, `gamma`, `dirQ`, `dirQ0`, `dmin/dscale` | uniform / constant buffer | 5 float4 + 3 matrices |

Dispatch: 16 x 16 workgroups over the image, one thread per pixel, the five kernels fused in one shader
(no intermediates); with hooks, split at the hook boundaries and keep `e`, `q`, `d` as `RGBA16F`/`RGBA32F`
storage images. `log2` is a hardware instruction on GPUs, so `pxLogE` becomes `log2(x) * 0.30103`.
Tables are uploaded once per bake (`FilmTables` is exactly the upload payload; bake stays on the CPU, ~12 ms).

## 4. Data and packaging

* `core/data/film/profiles/*.json` + `SPEKTRAFILM_LICENSE.txt` + `NOTICE.md` + `CHANGELOG.txt`: CC BY-SA 4.0
  profile data of spektrafilm (Andrea Volpato), unmodified.
* `core/data/film/dapple.dfp` (1.2 MB): binary pack, `dapple film-pack <profiles_dir> <out.dfp>`.
  `FilmLibrary::loadPack / loadPackMemory` (Android assets) and `loadJsonDir` (desktop tests, regenerates the
  tables in ~4 s). Format **DFP2** (all integers and floats little-endian, written byte by byte, so the file is
  identical on every host):

  ```
  header   "DFP2" | u32 fileSize | u32 crc32(bytes 16..end) | u32 sectionCount     (the magic carries the version)
  table    sectionCount x { u32 tag, u32 offset, u32 length }
  sections ATTR (attribution) | UPSM (upsampling table) | CMAX (CAM16 chroma limit) | STCK x N (one per stock)
  ```

  A reader rejects a wrong size (truncation or trailing bytes) and a CRC mismatch, skips sections with an unknown
  tag (room for additive changes) and requires every known section to be consumed exactly. Every stock goes through
  `validateStock`, the same check the JSON loader uses: exact array sizes (81 x 3 spectra, 256 x 3 curves, window 4
  or 0, surface 45 or 0, layers 9 per curve sample or 0, model 9 + 9 + 9 or none), finite values (NaN is allowed
  only as "not measured" in spectra and density curves), positive model sigmas. All float arrays are float32: the
  grain sub-layers used to be float16, which made a pack-loaded library differ from a `loadJsonDir` one; they are
  now bit-identical (`film.pack_format`). The test fuzzes truncations, bit flips (CRC on and recomputed) and an
  appended unknown section.
* Push/pull is a profile choice (`kodak_portra_800_push1/push2`), as in the reference.

## 4b. Robustness contract

* **Validation.** `FilmParams::validate()` (called by `applyJson` and `FilmSimulator::setParams`) requires every
  numeric field to be finite and inside a range (blur radii <= 1e5 um, tile-path blurs <= 64 px, film format 1 -
  1000 mm, exposure compensation +-20 EV, print exposure 1e-3 - 1e3, curve gammas 0.01 - 100, ...). Anything
  outside returns an error naming the field; nothing is clamped silently. Pixel radii that depend on the image
  size are bounded when the spatial plan is built: mixture components are clamped to the image extent (a wider
  Gaussian is flat over the image) and the tile-path blurs to 64 px, so no parameter can request a huge
  allocation. Options of the reference that this engine does not implement (`output_gamut_compress.knee` /
  `lightness_compression`, `developer_exhaustion`, `enlarger.lens_blur`) were removed from the structs; the JSON
  parser accepts them only at their neutral value and otherwise fails with "not implemented", so they can never
  be silently ignored (and cannot be stale in the bake cache).
* **Exceptions.** Nothing throws across the public API. `ThreadPool::run` catches an exception on any worker,
  abandons the remaining chunks, waits for all workers and rethrows the first one on the calling thread;
  `render` / `renderRows` / `renderStaged` catch it (allocation failure, ...) and return false, `setParams`
  returns false with a message.
* **`setParams` is transactional** (strong guarantee): everything is built into locals and committed at the end, so
  a failed call (unknown stock, bad value, bake error, `bad_alloc`) leaves the previous parameters, tables and
  plan untouched.
* **Threads.** A simulator has one owner at a time; the supported multi-threaded entry is
  `acquireSimulator` / `SimulatorLease` (each caller gets its own instance). Independently of that, `setParams` /
  `setHooks` take an exclusive lock and the render calls a shared one, so a concurrent call can never observe
  half-updated tables (which parameters a racing render uses is unspecified). Spatial renders on one instance
  serialise on the plan / arena mutex.
* **Cache keys.** The bake key and the spatial-plan key are 128-bit hashes (two independent 64-bit lanes over the
  bit patterns of the fields), computed without allocation; `setParams` during a slider drag no longer formats
  JSON. `film.cache_keys` asserts that a spatial-only change never re-bakes and that each field group feeding the
  bake does.
* **Scratch memory.** Per-thread workspaces (`Scratch`: 64 B aligned) shrink back when a request is 4x smaller than
  a large buffer and are released by `film::trimMemory()` on each thread's next use.
* **Libraries.** The lazy library load runs outside the registry lock; a failed load is kept and reported by
  `film::lastLibraryError()`. The simulator pool shrinks back to 4 entries after a burst of concurrent leases.
  `acquireSimulator` replaces the simulator of the recycled pool entry on a (library, film, paper) miss: its baked
  tables belong to another stock and are discarded on purpose.

## 5. Accuracy

Against the reference renders `build/film/ref/*_nospatial.pfm` (Portra 400 + Endura, 1600 px, sRGB encoded):
mean dE2000 0.07 - 0.10, p95 0.13 - 0.22, max 0.4 - 1.6 (see the report). Reference probe values of spec 02
s8 (grey ramp, EV, print exposure, filter shift, preflash, black/white correction, scan of negative and slide)
agree to 1e-3 in linear sRGB. Baked vs. direct path: mean dE2000 0.05 (N = 33), 0.2 (N = 17), 0.014 (N = 65).

With spatial and stochastic effects (Portra 400 + Endura, defaults, vs `build/film/ref/*_full.pfm`, the two sides use
different noise realisations): dE2000 after a 4x linear-light box downscale 0.63 - 0.81 mean, which equals the
noise floor of two of our own seeds (0.63 - 0.81); after 16x 0.19 - 0.25 against 0.19 - 0.21 for seed vs seed, i.e.
the deterministic part differs by < 0.1 dE. Grain RMS in flat mid-grey patches (8-bit levels, encoded; R / G / B):
reference 3.77 / 2.17 / 2.40 (landscape), ours 3.75 / 2.16 / 2.41; 3.07 / 2.02 / 3.14 vs 3.06 / 2.02 / 3.12
(highcontrast); differences <= 2 %. `dapple film-compare --down N` and `dapple film-grain` reproduce the numbers.

## 5b. Determinism and scale notes

* Grain (and glare) are keyed by (seed, x, y, layer) in **image pixels**. A render is bit-identical for any tile
  decomposition and any thread count, but a 1600 px preview and the full-resolution render of the same photo show
  different grain patterns (the grain size in pixels also differs: it is derived from the pixel pitch on the film
  format). Previews are therefore not a grain preview; `preview_mode` switches the grain off.
* Borders use scipy-style *reflect* padding (also in the half-resolution pyramid). A GPU port that clamps or
  zero-pads would differ within a few filter radii of the image edge; implement the same reflect index there.
* `settings.tile_width / tile_height` (0 = default 256 x 64) is an execution hint; the result does not depend on it
  (tiles recompute their halo; `film.robust_render` asserts bit-identity for odd tile sizes and degenerate image
  sizes down to 1 x 1). `dapple film-bench` prints a tile sweep; on the (shared, loaded) development machine 128 x 64
  and 256 x 32 measured 3 - 7 % faster than the default 256 x 64 and 512 x 128 / 1024 x 64 20 - 40 % slower, but the run-to-run
  noise there was of the same size, so the default was not changed; re-run the sweep on a quiet machine before tuning.
* Per-pixel libm calls are gone from the spatial path: the enlarger-diffusion exposure encode and the highlight
  boost use the polynomial `exp2f_` through the `SpatialKernels` table (max relative error 3.3e-6, measured in
  `film.kernel_exp`; below one 8-bit code step everywhere).

## 6. Not implemented / open

* Spatial effects (doc 03): everything is implemented except the reference-only details listed in the report
  (enlarger `lens_blur` is dead code in the reference and rejected by the parser unless 0, `crop` / `upscale_factor` are not implemented, the diffusion
  filter kernel is the Gaussian-mixture surrogate instead of a point-sampled kernel clipped at half the image size).
* `mallett2019` upsampling, input colour spaces other than ProPhoto, output spaces other than sRGB, output
  gamut algorithms other than CAM16-UCS and `off`, `developer_exhaustion` of the print curve morph,
  black/white correction for a directly scanned positive film, `crop` / `upscale_factor`, `lut_mode`.
* The reference auto-exposure thumbnail uses nearest sampling with a Gaussian pre-filter; we use an area
  average (`resizeToLongEdge`).

## 7. Integration into the develop pipeline

`EditParams` carries the film keys (`film`, `film_paper`, `film_strength`, `film_exp`, `film_warmth`, `film_tint`,
`film_grain`, `film_halation`; docs/design/requirements.md 6.3). Without a `film` id (or when the id cannot be
resolved against the installed library) nothing changes: the develop output is bit-identical to the renderer before
the integration (24 renders compared by hash and byte for byte: direct / baked / region / interactive / RGBA8, with
geometry, curves, grading, grain, tonal class, looks, detail stages).

```
source (linear ProPhoto) -> geometry / region resample (cubic) -> x (white balance x 2^(exposure + film_exp))
   -> FilmSimulator (tone + colour + look are replaced; linear ProPhoto in, display sRGB out; the gain is folded
      into the 3x3 input matrix, so an un-rotated full frame is read in place, no pre-multiplied copy)
   -> curves (master + R/G/B) -> 3D LUT -> [blend with the normal pipeline by film_strength] -> vignette -> clamp
   -> detail stages (noise reduction, dehaze, clarity, texture, sharpen, the `grain` slider) -> 8 bit
```

* **Strength** blends the finished result of both pipelines in display space (`normal + s * (film - normal)`, both
  with curves / LUT applied; the vignette is affine so it commutes with the blend). At 100 % the normal pipeline
  (and its lattice, see `BakedLut`) is not evaluated at all; at 0 % the output equals the normal render exactly.
* **Caching.** `film::acquireSimulator(library, film, paper)` leases one of up to 4 pooled `FilmSimulator`s, each
  keeping its baked tables (raw LUT, curves, print+scan LUT, ~12 ms cold) and spatial plan. `setParams` re-bakes
  only when `bakeKey` changed (stock, paper, print warmth / tint, ...); the exposure offset is part of the input
  gain and grain / halation are spatial parameters, so dragging those re-bakes nothing. The spatial plan is rebuilt
  only when the digested parameters or the frame size change (`planKey`). Renders from different threads get
  different simulators (a lease is exclusive).
* **Resolution scaling.** Spatial effects are defined in film-frame micrometres. The renderer passes the pixel
  pitch (output pixel size in source pixels: 1 for the natural size, the region step for previews and zoom regions)
  so that `camera.filmFormatMm` becomes `35 mm * pitch * max(w, h) / max(source w, h)`; the halation of a 768 px and
  of a 384 px render of the same frame have the same spread (test: rms radius 0.0218 vs 0.0223 image widths).
  Interactive quality (`SpatialQuality::Interactive`) maps to the profile's `preview_mode` (no grain / DIR
  diffusion / blurs), `Off` to `disableSpatialAndStochastic()`.
* **Knobs.** `film_warmth` / `film_tint` move the enlarger yellow / magenta filtration (+-12 filter units at +-100;
  more yellow filtration = cooler print, so warmth is its negative), `film_grain` scales the grain particle area
  (amplitude ~ sqrt: 100 = reference, 0 = off), `film_halation` the halation and scatter amounts, `film_exp` the
  exposure at the camera in EV (the print exposure is not re-balanced: brighter / darker like the exposure slider,
  but without a re-bake).
* **Memory.** The film output lands in the render's float frame (a recycled `ScratchImage`, kept up to 8 MP) and is
  finished in place; an un-rotated full frame needs no input copy.
* **Tone / colour sliders.** Contrast, highlights, saturation, HSL, grading, `look`, `toneTarget` do not act on the
  film part; they only shape the normal pipeline that `film_strength < 100` blends in. `BakedLut::analysis` still
  describes the normal pipeline.
* **C API.** `dapple_film_load_pack(path)`, `dapple_film_load_pack_memory`, `dapple_film_set_pack_path` (lazy),
  `dapple_film_list_json`, `dapple_film_attribution` (dapple_c.h). The CLI looks for `DAPPLE_FILM_PACK` or
  `core/data/film/dapple.dfp` near the working directory (`filmtool::installDefaultLibrary`).

## 8. Streaming 8-bit path (develop pipeline)

For a full-strength film rendered to RGBA8 without neighbourhood stages, `Renderer::renderBakedImpl` calls
`FilmSimulator::renderRows`: the chain runs in 4-row bands through a thread-local tile (L2-resident), the consumer
(display curves, vignette, clamp, 8-bit encode) runs on the hot tile, and resampled frames (zoom, geometry, preview from
a larger source) fetch their rows straight into the band. No full-frame float buffer exists (26 MP: 312 MB of page
faults plus two more passes removed). GPU mapping: one compute dispatch per tile, the sink is the epilogue of the kernel.
Measured (i7-14700KF, 26 MP, RGBA8, median of 7): 203 ms -> 80 ms; 1600 px preview from a 26 MP source 17 -> 12 ms.
