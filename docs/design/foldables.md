# 折叠屏适配设计（大折叠 · 小折叠 · 阔折叠）

> 状态：已作废。2026-11-14 业主否决了这一版（按屏幕分区、沿折痕拆面板的思路，以及把阔折叠当作翻盖式的定义都不对）。保留仅供查阅平台机制和差距清单，布局方案不要照做。


版本 0.1（2026-11-14，待负责人审）。范围：三种折叠形态在每个姿态下的版式、连续性、触控与性能。只写设计，不改产品代码。依据：`guidelines.md` v0.8 第 0 节“因地制宜，适度适配”、6、7、15.1、15.2、15.6；`editor-panel.md` v0.7 第 7 节；`local-adjustments.md` v0.4；`audit-2026-11.md`（R9、R32、F25、F45–F47）；`requirements.md` 4.14、4.15.14、4.15.15。线框图在 `foldables/`（SVG，亮色，指南令牌）。

## 0. 结论

| 形态 | 姿态 | 照片在哪 | 控件在哪 |
|---|---|---|---|
| A 大折叠（书本式） | 合上 | 外屏 = 手机设计 | 同手机 |
| | 展开平放 · 横构图 | 全宽在上，可以跨过平放的折痕 | **分左右**：惯用手那半屏是页眉 + 强度条 + 盘面，另一半是坞 + 直方图（两个拇指各管一个下角） |
| | 展开平放 · 竖构图 | 照片列（可跨折痕） | 侧窗格整块在惯用手半屏，坞在窗格底 |
| | 桌面姿态（转 90° 立起，折痕水平） | 上半，只有照片 | 下半：顶栏一行 + 与平放相同的“分左右” |
| | 书本姿态（半开，折痕竖直） | 非惯用手那一半 | 惯用手那一半是完整控制页（顶栏、页眉、盘面、坞） |
| B 小折叠（竖折式） | 展开平放 | 多出来的高度给照片 | 同手机，面板用“舒适”高度 |
| | 半开立着 | 上半 | 下半全部控件，含顶栏 |
| | 外屏 | 到达监视：最新传来的一张铺满 | 不编辑；不能上外屏的机型只靠系统通知 |
| C 阔折叠（竖向展开、16:10） | 展开竖持 | 横构图几乎满宽，正好在折痕之上 | 手机版式，宽度用来让控件一行放下、两块盘面并排 |
| | 横持（707×440 一类） | 照片列 | 侧窗格（高度紧凑），半开 = 书本姿态 |
| | 半开悬停 | 上半；**顶栏也留在上半两角**（下半放不下） | 下半：页眉 + 强度条 + 盘面 + 坞 |
| | 外屏（约 1:1） | 看片、挑片、分享 | 不编辑（打开手机就在编辑器里接着这一张） |

今天的实现与此的主要差距（详见第 9 节）：应用里**没有一处读 `displayFeatures`**；所有宽屏判断只看宽度（600 / 720）；内屏上横构图照片只得到约 488×325 dp，上下各空约 170 dp；首页网格、工具页的大图与主按钮、发布页的分栏线都压在或切过折痕；缩放位置按屏幕 dp 存，折叠 / 展开后会看到照片的另一块；测试里没有任何折痕。

## 1. 三种形态的事实

数值来自官方页面（见第 14 节）。dp 由像素和像素密度估算，实际 dp 取决于厂商设定的密度档，**以真机为准【待验】**；设计不依赖这些数，只依赖运行时读到的尺寸和折痕。

| 形态 | 屏 | 尺寸示例（官方） | 比例 | 估算 dp | 本文线框 |
|---|---|---|---|---|---|
| A 大折叠 | 内屏 | 8.0″ 2076×2152 px；另一款 8.0″ 2184×1968 px（368 ppi） | 近方形，约 1.04–1.11 | 约 890×920 / 950×855 | 904×832（折痕竖直）与 832×904（转 90°） |
| | 外屏 | 6.3″ 1080×2424 px（422 ppi）；6.5″ 2520×1080 px（21:9，422 ppi） | 约 21:9 | 约 410×920–960 | 411×960 |
| B 小折叠 | 内屏 | 6.9″ 2520×1080 px（21:9）；6.9″ 2640×1080 px | 21:9–22:9 | 约 412×960–1004 | 412×1004 |
| | 外屏 | 4.1″ 1048×948 px；3.6″ 1056×1066 px；4.0″ 1272×1080 px | 近方形 | 密度未公布 | 360×380 |
| C 阔折叠 | 内屏 | 6.3″ 2120×1320 px，16:10 | 竖持约 1.61 | 厂商逻辑尺寸 440×707；按约 396 ppi 估算 533×857 | 440×707 |
| | 外屏 | 3.5″ 980×980 px，1:1 | 1:1 | 厂商逻辑尺寸 326×326；估算约 396 见方 | 326×326 |

- 大折叠：展开后两半各像一台手机（约 410×900），折痕竖直把宽度分成两半；**两种朝向都常见**（有的机型展开后略高于宽，有的略宽于高），所以设计只看折痕在哪，不假设方向。
- 小折叠：展开就是一台更高的手机；折痕水平在中间。
- 阔折叠：铰链水平，展开竖持是比手机宽的 16:10，合上是接近方形的机身和 1:1 外屏。目前公开的阔折叠运行 HarmonyOS，本应用（Flutter Android）不能直接装【待验】；同一厂商的下一代是横向展开、约 1.41:1、外屏也不是 1:1，安卓阔折叠只有传闻。**所以 C 的设计同样按尺寸写，任何“竖向 16:10 + 水平折痕 + 方形外屏”的窗口都会得到它**，将来移植或别家出同类机型时不用重写。

## 2. 原则落到折叠屏

1. **照片最大，不留空白带**（指南 0、R9）。在大内屏上浪费上下 170 dp 的空白，比把面板放得“像平板”更违反原则。
2. **含义处处相同**（指南 0 的检验：用户去了别处，还知道这个动作做什么）。变化的只有位置。
3. **折痕是硬件事实，不是装饰**：平放时它是一道看得见、摸得到的棱；半开时它把屏幕分成两块朝向不同的面。可点的东西不放在上面。
4. **两只手各干一件事**：大屏双手握时，惯用手做细活（盘面、强度条、画笔），另一只手定框架（选分类、开关、撤销）。这是双手分工的经典结论（Guiard 1987）：非惯用手给出参照和模式，惯用手在其中做精细动作。
5. **姿态改变 = 布局改变，状态不变**（第 7 节）。

## 3. 共用规则（按尺寸类别与姿态，不按机型）

### 3.1 尺寸类别

沿用安卓的窗口尺寸类别（宽：紧凑 < 600、中等 600–839、扩展 840–1199；高：紧凑 < 480、中等 480–899、扩展 ≥ 900），按**当前窗口**算，不按设备：

| 窗口 | 宽 | 高 | 落在哪个设计 |
|---|---|---|---|
| 大折叠外屏 411×960 | 紧凑 | 扩展 | 手机 |
| 大折叠内屏 904×832 | 扩展 | 中等 | A 平放 / 书本 |
| 大折叠内屏 832×904 | 中等（差 8 dp 到扩展） | 扩展 | A 平放 / 桌面 |
| 小折叠展开 412×1004 | 紧凑 | 扩展 | B |
| 小折叠半开的每一半 412×≈480 | 紧凑 | 中等的下沿 | B 半开 |
| 小折叠外屏 360×380 | 紧凑 | 紧凑 | 小窗（B 外屏） |
| 阔折叠展开 440×707 | 紧凑 | 中等 | C 竖持 |
| 阔折叠横持 707×440 | 中等 | 紧凑 | C 横持（同手机横屏） |
| 阔折叠外屏 326×326 | 紧凑 | 紧凑 | 小窗（C 外屏） |

尺寸类别只用来挑“候选版式”；**最后选哪个由照片面积决定**（`editor-panel.md` 7 的做法）。832 与 904 的宽度落在不同类别，但两者都要得到大折叠的设计，所以不拿 840 做开关，而是看“放不放得下”（3.3）。

### 3.2 折痕与铰链

从 `MediaQuery.displayFeaturesOf` 读到类型为 fold / hinge 的项（第 11 节），得到折痕的方向和位置，再分两种：

| | 判定 | 照片 | 可点的控件 |
|---|---|---|---|
| **不分屏**（平放的折痕） | fold 且状态 = 平放 | 可以跨过 | 离折痕线 ≥ 16 dp（淡红禁区） |
| **分屏**（半开，或任何 hinge） | 状态 = 半开，或类型 = hinge | 只在一块里，离铰链 ≥ 16 dp | 离铰链 ≥ 40 dp；对话框、菜单、提示条不跨铰链 |

- 16 / 40 沿用指南 15.6（来自 HarmonyOS 悬停规范，那份规范对上半 16、下半 40 的数值与此一致）。
- 不可点的东西（读数、直方图、照片本身）可以跨平放的折痕；读数改为在**照片区**上缘居中，而不是屏幕居中（屏幕中线正是折痕）。
- 半开时屏幕分成两个“可用区”，每个区按自己的大小再用一遍 3.1 / 3.3。

### 3.3 编辑器的版式候选

三种候选，各自算出照片框，取照片面积最大者（侧窗格仍要大 8 % 才赢，防抖动）：

1. **下方**：照片在上，面板 + 坞在下（手机竖屏）。
2. **一侧**：照片列 + 惯用手侧的窗格，坞在窗格底，顶栏竖排在照片列外侧（手机横屏、大折叠竖构图）。
3. **分左右**（新）：照片全宽在上；底部一条控件带被折痕（或屏幕中线）分成两半：惯用手半屏 = 页眉 + 强度条 + 盘面，另一半 = 坞 + 直方图 + （局部时）工具条。**只在“宽度能给两半各放下一个坞（≥ 336 + 边距）”时成为候选**，即宽 ≥ 720 dp；现在只有大折叠内屏满足，阔折叠横持（707）不满足。

姿态会**强制**候选：

| 姿态 | 强制 |
|---|---|
| 分屏、折痕水平（桌面 / 悬停） | 照片在上块，控件在下块；下块放得下“顶栏一行 + 面板（盘面 ≥ 150） + 坞”时顶栏也下来，否则顶栏留在上块两个上角 |
| 分屏、折痕竖直（书本） | 照片在非惯用手块，惯用手块是完整控制页 |
| 不分屏 | 不强制，按照片面积选 |

例（照片面积，dp²）：904×832 平放横构图：一侧约 488×325（今天）对分左右约 678×452，分左右胜；竖构图：一侧约 468×702 对分左右约 301×452，一侧胜。

### 3.4 惯用手

- 设置里的 自动 / 左手 / 右手（`models.dart` `handedness`）与被动推断沿用；它决定：编辑器窗格、分左右的盘面半屏、首页网格窗格、导入网格窗格在哪一侧。
- 推断在双手握大内屏时不可靠（两个拇指都在点）：推断器已有双手检查，**检测到双手时保持上一次的边**，不翻转。
- 发布、工具、设置这类表单不镜像（内容在前、选项和主按钮在后），主按钮在后半屏底部，右手最近；左手用户的这点代价可接受（表单只点一次主按钮）。
- 换边只在抬手后的空闲期，用大弹簧（指南 15.1-7、15.3）。

### 3.5 统一的交互，在每个版式里一模一样

| 交互 | 规则 | 折叠屏上要注意的 |
|---|---|---|
| 按住照片 = 对比（U4） | 380 ms 不动，松手恢复 | 照片跨平放折痕时，起点在折痕禁区内也算（照片不是控件）；首页预览、外屏看片也同样按住看原片 |
| 再点已选中的 = 动作卡（U3） | 芯片、人像芯片 | 动作卡原地替换面板身体，不弹到另一半屏 |
| 强度条（U1） | 下 0、中线 100 %、上 = 最多 | 永远在盘面的外侧（靠屏幕边），高度跟盘面；分左右与书本姿态里都在惯用手半屏 |
| 分项 | 页眉最后一个按钮 | 位置在页眉右端，与手机相同 |
| 加 / 减开关（U2） | 工具条左端 [+|−] | 工具条在非惯用手半屏时，开关在它的外端（靠屏幕边） |
| 页眉（U6） | `[‹] 标题 · 读数 …（复位）· 主动作` | 不变 |
| 坞 | 六项，每项 ≥ 48 | 分左右时坞单独在另一半；含义、顺序、按住弹出盘面都不变 |

### 3.6 触控目标、安全区、系统手势

- 命中区 ≥ 48 dp（指南 6）；大屏不放大控件“凑面积”，但盘面、强度条这类连续控件跟着可用空间长（Fitts：目标越大、离拇指越近越快）。
- inset、系统手势区、刘海、折痕全部运行时读取（指南 15.6）；控件离侧边 ≥ max(12, 该侧手势 inset)，底部控件在 max(底 inset, 底手势 inset, 16) 之上。
- 本应用不声明手势排除区：安卓的返回手势排除每条边最多 200 dp，底部的强制手势区根本不能排除；把控件内缩比排除更稳。
- 外屏没有导航手势条的机型（各家不同）同样只读 inset。

### 3.7 三种设计哪里共用、哪里必须不同

| | 共用（由规则算出） | 必须不同（形态本身决定） |
|---|---|---|
| 折痕处理 | 3.2 一张表 | 大折叠的折痕竖直分宽度；小、阔折叠的折痕水平分高度 |
| 版式选择 | 3.3 三个候选 + 照片面积 | 只有大折叠内屏宽到能“分左右” |
| 半开 | 3.3 的姿态强制 | 小折叠下半放得下顶栏，阔折叠放不下（按尺寸判断，结果不同） |
| 外屏 | “小窗”规则：宽高都 < 480 时不进编辑 | 大折叠外屏是一台完整手机（全部功能）；小折叠外屏只做到达监视；阔折叠外屏做看片、挑片、分享 |
| 惯用手 | 3.4 | 大折叠双手握为主，小 / 阔折叠单手为主 |

实现上就是：一个纯函数从（窗口尺寸、inset、折痕、惯用手、照片比例、当前层需要的高度）算出版式；没有“如果是某某机型”。

## 4. A 大折叠（书本式）

### 4.1 姿态

| 姿态 | 怎么识别 | 设计 |
|---|---|---|
| 合上 | 窗口约 411×960，没有折痕 | 手机设计，规则全部照用（`A1-closed-cover-editor.svg`） |
| 展开平放 | 有 fold、状态平放 | 不分屏；按 3.3 选“分左右”或“一侧” |
| 桌面姿态 | 半开，折痕水平（内屏转 90° 立起，像笔记本） | 上看下操作 |
| 书本姿态 | 半开，折痕竖直（像拿着一本书） | 左右各一块 |

**外屏（合上）**：新机型外屏约 411 dp 宽，和普通手机一样；旧的窄外屏可能不到 360 dp【待验】，那时用指南已有的窄屏规则：页眉“强度 N %”永远完整、方向读数先让位；坞每项 ≥ 48，放不下就横滑，不缩项；局部工具条放不下时向上长第二行；裁切比例两行各三个；面板盘面不低于 150。

### 4.2 拇指可达（`A0-reach-book.svg`）

- 双手握在两侧偏下（握点约在屏高 60 %），拇指舒适半径约 45 mm（≈ 280 dp）、伸直约 65 mm（≈ 410 dp）（数值是估计，取自拇指功能区研究的量级，待真机测）。两个拇指各管一个下角；**离两个拇指都最远的是正中和上沿**，正好是折痕和顶栏。
- 一只手托、另一只手食指点：整屏都够得到，Fitts 意义上的“距离”变成食指悬停处到目标的距离；托的那只手的拇指只管它那一侧边带。
- 手掌与拇指根遮住拇指下方：所以照片不放在操作手的下方，读数放在照片上缘。

结论：**控件放两个下角，折痕和上沿只放不需要点的东西。**

### 4.3 每个屏幕

**首页**（`A2-flat-home.svg`，书本姿态 `A4-book-home.svg`，桌面姿态 `A3-tabletop-home.svg`）
- 平放 / 书本：两窗格，以折痕为界。网格在惯用手半屏（3 列，每格约 140 dp，整块不被折痕切开）；另一半是**预览**：点一张 = 大图 + 拍摄信息 + 建议检查；按住预览 = 看原片；「编辑」或双击网格打开编辑器（全屏）。
- 为什么值得：挑片是摄影师在大屏上最常做的事；今天每看一张都要进编辑器（开引擎会话），预览只需要已有的 1280 px 预览图，又快又省。
- 导航轨在前缘，三项**靠下**排进左拇指的弧（今天顶在左上角）。顶栏的状态与动作（连接状态、拍照、导入、选择）在网格窗格上方。
- 选择模式：底部选择栏只在网格窗格内。
- 桌面姿态：上半大图（给人看片），下半缩略图条横滑 + 标题行动作 + 底部导航栏（下半高度不到 480，用导航栏不用导航轨）。

**编辑器：六个分类**
- 光线、颜色、成像、质地（盘面类）：横构图走“分左右”（`A2-flat-editor-landscape.svg`），竖构图走“一侧”（`A2-flat-editor-portrait.svg`）。盘面在惯用手半屏，强度条在盘面外侧。直方图是常驻小窗，在非惯用手一侧（分左右时在坞上方，一侧布局时在照片列上角）。
- 成像地图（`A2-flat-filmmap.svg`）：替换盘面的位置，大小相同（同一分类内盘面、地图、复杂编辑器同高，`editor-panel.md` 7）；按住放大 2.4 倍、按压 - 滑动 - 松手选片不变。
- 局部 / 人像（`A2-flat-local.svg`）：照片上是手柄与红色范围；惯用手半屏是页眉、区域芯片（第二行）、两块并排盘面 + 强度条；**工具条在非惯用手半屏坞的上方**，[+|−] 在外端。分工：左拇指切加 / 减、换粗细，右手指在照片上画——比今天把工具条放在照片正下方（在折痕附近、离两个拇指都远）好。人像的部位芯片层、祛斑同理。竖构图走一侧布局时，工具条仍按 `local-adjustments.md` 5 在照片下自己的一行，但左对齐到照片列外侧，不居中压在折痕上。
- 裁切（`A2-flat-crop.svg`）：照片全宽带三分线；比例六个一行（每个 ≥ 48）、旋转 / 翻转一行、拉直尺子在最下（最常连续拖，离拇指最近）。
- 顶栏：分左右时在两个上角（返回左上，胶囊右上）；一侧布局时竖排在照片列外侧，**靠下对齐到左拇指的弧**（返回在最上，撤销 / 重做在拇指够得到的高度），今天是顶在左上角。
- 按住坞项弹出盘面：弹在坞项上方，跟坞在同一半屏，不跨折痕。

**桌面姿态**（`A3-tabletop-editor.svg`）：上半只有照片（立着的屏被点会晃）；下半第一行是顶栏，下面是与平放相同的“分左右”。展开回平放时照片向下长大，下半的控件原位不动。

**书本姿态**（`A4-book-editor.svg`）：照片退回非惯用手那一半；另一半是完整控制页：顶栏一行、页眉、强度条 + 盘面（更高）、坞。横构图在半屏里会变小（约 424×283），这是书本姿态的代价，不另想办法：用户想看大图就会放平。

**发布**（`A2-flat-publish.svg`）：两栏以折痕为界：左 = 要发的照片（两列大缩略图）+ 发到哪里（两列预设卡）；右 = 选项卡 + 警示卡 + 「分享…」在右下。不论内屏横竖都用两栏（今天竖着拿时会退成一栏居中）。

**工具**（`A2-flat-tools.svg`，全景、包围、实况同一模式）：结果预览占满左半；参与的照片、选项、主按钮在右半。桌面姿态里实况的片段条与预览天然是“上看下操作”。

**导入（从相机选）**（`A2-flat-import.svg`）：网格在惯用手半屏，最近点到的那张在另一半看大图（导入前判断对焦和曝光）；「导入 n 张」在网格下方。导入进度不占这里，回首页后在连接卡和格子里显示，与手机相同。

**设置、成像页**：已有“左列表右详情”；把分栏线对齐到折痕（今天左列固定 340 宽）。

### 4.4 两窗格：值得的与不值得的

| 机会 | 结论 | 理由 |
|---|---|---|
| 首页 网格 + 预览 | 值得 | 挑片是主任务；预览不开引擎会话 |
| 编辑 照片 + 面板并排 | 值得（竖构图）；横构图用“分左右” | 由照片面积算，不是规定 |
| 导入 网格 + 大图 | 值得 | 导入前要判断对焦 |
| 发布、工具 内容 \| 选项 | 值得 | 表单天然两栏，主按钮落到拇指处 |
| 编辑时 原片 \| 成片 并排 | **不值得** | 每张只剩半屏；同位置按住切换更容易看出差别（并排要靠眼动和记忆比较，翻转让差别“跳出来”，见变化盲视的闪烁范式）；需求 4.15.6 已取消并排，折叠屏不复活它 |
| 编辑时 两张照片对照（同步设置） | 不做 | 同步已有自己的流程；两张小图不如一张大图 |
| 编辑时 左边网格 右边编辑器 | 不做 | 照片会小一半；编辑需要整块屏 |

## 5. B 小折叠（竖折式）

### 5.1 展开平放（`B1-open-editor.svg`）

一台 412×1004 的高手机。多出来的高度：
1. **全部给照片**（竖构图收益最大）；
2. 面板固定用“舒适”高度（盘面 236），不因屏高而变高，不加控件，不加第二个窗；
3. 折痕在照片中段，平放不分屏，照片可以跨；面板与坞都在折痕下方。

首页、发布、工具、导入、设置：与手机相同（宽度紧凑，3 列网格）。

拇指（`B0-reach-flip.svg`）：单手握在下部，上部约 40 % 够不到。顶栏（返回、撤销）在最上，与手机一样需要换手；不为它另造手势（会破坏“同一个动作同一个意思”）。系统自带的单手模式照常可用。

### 5.2 半开立着（`B2-flex-editor.svg`、`B2-flex-review.svg`）

- 编辑：上半只有照片；下半 = 顶栏一行 + 页眉 + 强度条 + 盘面（下半约 480 dp，放得下舒适高度）+ 坞；控件离铰链 ≥ 40。
- 首页变成**看新到的照片**：拍摄间隙把手机立在桌上，相机传来的照片在上半自动出现；下半是接收状态、缩略图条、「回到最新」「编辑」、底部导航栏。这是小折叠半开唯一真正有用的新场景。
- 拍照入口用的是系统相机，本应用不做取景器，所以不做“半开当三脚架拍照”。

### 5.3 外屏（`B3-cover.svg`）

诚实地说：
- 各家外屏是否允许第三方应用不同：有的只放行少数应用，有的需要用户逐个允许；**没有通用的公开接口**让应用为外屏另做一套界面。
- 值得做的只有一件：**到达监视**——外屏是应用窗口时（约 360×380 这类宽高都 < 480 的窗口），显示最新传来的一张铺满，左右划翻看最近到达，左上实底胶囊写接收进度与连接状态，失败变琥珀色并写原因；不编辑、不发布、不选成像。
- 应用上不了外屏的机型：靠系统通知。今天的接收服务（`FtpService.kt`）发的是只有文字的前台通知，**应加进度**（已收 n / 共 m），系统会把它带到外屏或锁屏上。这是唯一需要的原生改动。
- 不做：外屏快门（拍照走系统相机）、外屏编辑（屏太小，盘面会盖住照片）、外屏小组件（各家规则不同，收益小）。

## 6. C 阔折叠（竖向展开、16:10）

### 6.1 展开竖持（`C1-open-editor.svg`、`C1-open-local.svg`）

约 440×707（宽度紧凑、高度中等），比手机宽约 7 %，比手机短约 25 %。宽度用来：
- 横构图照片几乎满宽（约 416×277），照片区正好在折痕之上；
- 坞六项一行放下不横滑，页眉读数与方向都完整；
- 局部：两块盘面并排、工具条一行放下四档粗细；裁切比例一行六个。

高度短，所以面板严格用手机规则（照片 ≥ 无面板时的 90 %，盘面 ≥ 150）；竖构图照片会比较小（约 186×279），这时横持更好（6.2）。首页 4 列网格（每格约 106），其余页面同手机。

拇指（`C0-reach-wide.svg`）：机身约 70 mm 宽，单手拇指能扫到对边下部；坞、强度条、盘面都在舒适区；上部约 35 % 单手够不到（顶栏，同手机）。

### 6.2 横持（`C2-landscape-editor.svg`）

约 707×440（宽中等、高紧凑）：等于手机横屏，走“一侧”：顶栏竖排在照片列外侧，侧窗格在惯用手侧（左缘离折痕 ≥ 16），坞在窗格底。宽 707 < 720，不提供“分左右”。竖构图在这里更大（约 261×392），横构图则竖持更大：由求解器按照片面积选，**不提示用户转屏**。半开成书本姿态时同 A 的书本姿态（照片退回左半）。

### 6.3 半开悬停（`C3-hover-editor.svg`）

上半约 440×337 看照片，下半约 440×314。下半放不下“顶栏 + 面板 + 坞”（盘面会低于 150），所以**顶栏留在上半两个上角**（返回、撤销偶尔点，轻点），下半是页眉 + 强度条 + 盘面（约 153）+ 坞。这与小折叠半开（顶栏下到下半）的差别完全由下半高度决定，按 3.3 的规则自动得出。首页悬停 = 小折叠的“看新到的照片”同一设计。

### 6.4 外屏（`C4-cover.svg`）

约 326×326（估算约 396 见方），能真正用，但做取舍：

| 任务 | 外屏做不做 | 理由 |
|---|---|---|
| 看片（网格 3 列、点开全屏、左右划、按住看原片） | 做 | 合上时最常见的需求；按住对比与别处同义 |
| 挑片（星标、删除） | 做 | 一个动作一下，单手可达 |
| 接收状态 / 到达 | 做（格子里的进度、顶部状态） | 同首页 |
| 分享已编辑的成片 | 做（系统分享） | 发布的“快速一步”；平台预设与选项在内屏 |
| 编辑（盘面、局部、裁切、人像） | 不做 | 326 高里“照片 + 面板 + 坞”放不下；按住坞项弹出的 216 dp 盘面会盖住整张照片，违背“看着照片调” |

打开手机时在内屏的编辑器里接着这一张（第 7 节）。这一档“小窗”规则（宽高都 < 480）也用于小折叠外屏和分屏里很小的窗口。

## 7. 连续性：折叠 / 展开 / 换姿态的中途

清单（姿态变化前后必须相同）：当前照片；缩放倍数与**看到的那一块**（按图像坐标存中心点，不按屏幕 dp）；选中的分类；所在的层（盘面 / 分项 / 地图 / 复杂编辑器 / 卡片）；局部的当前区域与当前块；人像芯片；裁切框；首页的滚动位置、选择集、预览中的那张；发布页的选项。

拖动中途：
- 换姿态（同一块屏，平放 ↔ 半开）：触摸流不断，拖动继续，**交互中不重排**（15.1-7）：新版式在抬手后才生效。
- 换屏（内屏 ↔ 外屏）：系统会取消这次触摸。按**提交**处理：值停在最后一刻，算一个撤销步（与松手一样），不回滚；按住对比自然结束；按住坞项弹出的盘面收起，值保留。

动效：
- 同一块屏换姿态：照片框、面板、坞三个矩形一起用大弹簧（350 ms，15.3）插值到新位置；照片保持图像中心。减少动态效果时改为 150 ms 渐变。
- 换屏：旧屏已经不在了，从旧几何插值没有意义：新屏直接按新版式出现，照片在原缩放与原中心，控件 150 ms 淡入；不做“飞过来”。
- 惯用手换边、窗口类别变化：同上，大弹簧，只在空闲期。

美学：版式变化时照片是锚，界面元素绕着它移动，而不是照片跟着界面跳；照片框在新区域里居中，四周留白相等（舞台灰，指南 1.5）。

## 8. 推理：人机与美学

- **够得着（可达）**：大内屏双手握时，最远的是中线和上沿；所以分左右（4.2）。小 / 阔折叠单手握时，最远的是上部；所以多出来的高度给照片而不是控件（5.1、6.1）。
- **Fitts**：移动时间随距离增加、随目标宽度减少。把连续控件（盘面、强度条、尺子）放在拇指舒适区并让它们长大，比把它们居中在两个拇指都要伸长才够得着的地方快；离散的小按钮（复位、分项）放在页眉右端，离惯用手拇指近。
- **遮挡**：手在照片上方时会挡住正在看的东西。分左右里操作手在照片的一侧下方，照片完整可见；局部画笔是唯一要在照片上动手的，用食指且照片足够大。
- **注意力在照片上**：读数在照片上缘、直方图在非惯用手侧；用户调的时候眼睛不离开照片，手的位置靠肌肉记忆（位置在各姿态间不变：桌面姿态与平放的下半一模一样）。
- **双手分工**（Guiard）：非惯用手选分类、切加 / 减、撤销；惯用手做连续调整与绘制。
- **对比方式**：同位置按住切换优于并排（4.4）。
- **平衡与构图**：分左右时，照片是上方的大块，下方左右两块控件左轻右重（直方图 + 坞对盘面），视觉重心落在照片；一侧布局时照片列居中于剩余宽度，不贴边；书本姿态里照片在半屏内居中，左右留白相等，铰链两边像书的两页。
- **折痕不切照片的关键处**：平放时照片可以跨折痕，但不让任何文字、按钮、读数的字压在折痕上；半开时照片完全在一块里（倾斜的面上看照片会变形、反光不同）。

| 屏幕 | 今天 | 提议 | 差距 |
|---|---|---|---|
| 展开竖持 440×707 | 手机设计；坞和页眉在 440 宽下放得下 | 同，宽度换成一行放下的控件 | 小 |
| 横持 707×440 | 手机横屏的一侧布局 | 同，加折痕禁区 | 折痕 |
| 半开悬停 | 不识别 | 上照片、下控件、顶栏留上半 | 全无 |

| 平台 | 本应用是安卓应用，这类机器目前跑 HarmonyOS【待验】 | 设计按尺寸写好；是否移植另行决定 | 见第 13 节 |

## 10. 无障碍与性能

**无障碍**
- 读屏顺序跟视觉分区：分左右时先照片，再惯用手半屏的页眉、强度条、盘面，再另一半的坞；两窗格首页先网格后预览。每个区域是一个语义容器（`Semantics(container)`），读屏能整块跳过。
- 姿态变化时用一句播报说明（“已切换到上下两半”/“已切换到左右两半”），不移动读屏焦点。
- 大字号：页眉 ≥ 130 % 时按钮另起一行（12.6）；分左右的控件带随之变高，照片让位；半开时下块放不下就把坞改为横滑，不截断文字。
- 按住类手势都有语义动作（看原片、放大 / 适合），与手机相同；外屏看片同样提供。
- 对比度、命中区下限不因屏大而放宽。

**性能**
- 预览分辨率：闲时帧长边 = 照片在屏上的物理像素，夹在 1080–2048（`editor_engine.dart` `setDisplayLongEdge`）；拖动帧不超过 1080。内屏上分左右的横构图约 678 dp ≈ 1600–1700 px，竖构图一侧约 702 dp 高 ≈ 1650–1850 px，都在 2048 内，不用改上限；拖动帧在大屏上会放大约 1.6 倍，松手 150 ms 后清晰，可接受，先测再说。
- 换姿态的代价：版式求解是纯函数（微秒级）；贵的是新尺寸的重渲染和首页缩略图换尺寸。规则：换姿态时先把当前帧缩放显示，不出现空白；视口报告已有 120 ms 防抖（`zoom_view.dart`），弹簧收敛后只重渲一次；缩略图按尺寸档缓存（如 128 / 192 / 256），半屏与全屏的格子尽量落在同一档。
- 面板在姿态动画中不重建（`debugPanelBuilds` 断言照用），三个矩形只做位置插值。
- 两窗格首页的预览只用已提取的 1280 px 预览图，不开引擎会话；打开编辑器时再开。

## 11. Flutter 机制

**安卓上不需要新依赖就有的**
- `MediaQuery.displayFeaturesOf(context)`：`DisplayFeature` 的 `bounds`（逻辑像素）、`type`（fold / hinge / cutout）、`state`（平放 / 半开 / 未知）；只在安卓上有值，其他平台为空；变化时触发重建。本仓库用的 Flutter 内嵌层依赖 `androidx.window:window-java:1.2.0`（gradle 缓存里的内嵌层 POM），数据来自 Jetpack WindowManager。
- 方向：bounds 宽 < 高 = 竖直折痕；“分屏”Flutter 不直接给，用 3.2 的规则推出（半开或 hinge = 分屏；安卓文档：半开时 `isSeparating` 总为真）。
- `DisplayFeatureSubScreen`：对话框、底部面板、菜单默认避开分屏的折痕（Flutter 3.0 起模态路由支持），用 `anchorPoint` 决定落在哪一半。
- `MediaQuery.sizeOf / paddingOf / viewPaddingOf / systemGestureInsetsOf`：尺寸类别、inset、手势区。
- 测试：`tester.view.displayFeatures`（`flutter_test` 的 `TestFlutterView`）可以注入折痕。
- `AndroidManifest.xml` 的 `configChanges` 已含 `orientation|screenSize|smallestScreenSize|screenLayout|density`：折叠 / 展开不重建 Activity，Flutter 只是收到新尺寸；进程被杀后的恢复仍要靠已有的状态保存。

**需要原生代码（Kotlin，`androidx.window` 已在类路径上，不加依赖）**
- 强制系统手势区（`WindowInsets.getMandatorySystemGestureInsets()`）：15.6 已计划的平台通道。
- 折痕遮挡类型（`occlusionType`）：目前不需要，规则已按最坏情况留禁区。
- 后屏 / 双屏显示模式（`WindowAreaController`）：不需要。
- 铰链角度：WindowManager 不给，不需要。
- 外屏：没有通用接口；只改接收服务的通知加进度（`FtpService.kt`）。

**不用**：第三方折叠屏包（`dual_screen` 的 `TwoPane` 等），自己的版式求解器已经够，并且要遵守本指南的照片优先规则。

## 12. 实施步骤与测试

按顺序，每一步可单独验收：

1. **屏幕形状模型**（纯 Dart，`lib/editor/screen_shape.dart`）：输入 `MediaQueryData`（尺寸、inset、手势区、`displayFeatures`）与惯用手，输出尺寸类别、折痕（方向、位置、是否分屏）、姿态（平放 / 桌面 / 书本 / 无）、可用区列表、禁区。单元测试覆盖第 3.1 表的每一行。
2. **测试设施**：`test/audit/audit_support.dart` 增加尺寸与折痕（下表）；一个通用断言：渲染树里所有可点击的命中框不与禁区相交（遍历 `RenderPointerListener` / 语义按钮的全局矩形）。
3. **编辑器版式**：`panel_layout.dart` 加禁区约束、“分左右”候选、姿态强制、“下块放不放得下顶栏”判断；矩阵测试扩展到所有新尺寸；断言照片面积不小于提议值。
4. **编辑器摆放**：顶栏 / 竖排顶栏靠下、坞（可在另一半）、直方图、读数（照片区居中）、提示条、按住弹出、局部工具条（另一半）；`DockedPanelHost` 支持分左右的身体。
5. **连续性**：缩放按图像坐标存中心；换姿态大弹簧、换屏直接出现；换屏取消的拖动按提交；widget 测试：同一棵树先 904×832 平放再换 411×960 再换回，断言分类、层、区域、缩放中心不变，撤销步数 +1 只发生在被取消的拖动上。
6. **首页两窗格**：预览窗格、导航轨靠下、网格对齐折痕、桌面姿态的看片版式。
7. **发布、工具、导入**：两栏对齐折痕，去掉 `width >= height` 条件；导入加大图。
8. **半开版式**：小折叠与阔折叠的上下两半（编辑、看新到的照片）。
9. **小窗**（宽高都 < 480）：外屏看片 / 到达监视；编辑入口不出现。
10. **通知加进度**（`FtpService.kt`，原生）。
11. **文档**：指南 7（删去机型假设的几何表，改指向本文）、15.6（3.2 的表）、`editor-panel.md` 7（第三个候选）、审查清单加“折痕禁区”一条；`requirements.md` 4.14 / 4.15.14 指向本文。

## 14. 未能核实 / 待验

- 各机型的真实 dp 与密度档（本文 dp 由官方像素与 ppi 估算；厂商逻辑尺寸只对阔折叠有官方数）。
- Flutter 在单屏折叠机上平放时是否报告 fold（安卓 WindowManager 平放时会报，Flutter 是否原样转交未见官方说明）；是否对小折叠报告折痕。
- 拇指舒适 / 可达半径（45 / 65 mm）是按研究量级给的估计，需真机测。
- 各家外屏对第三方应用的放行规则（只查到消费者帮助页，没有开发者文档）；阔折叠机型能否运行安卓应用（官方页只写系统版本）。
- 返回手势排除“每边 200 dp”的确切措辞（来自安卓手势导航文档与 codelab 的转述）。
- 16 / 40 dp 的铰链间距来自 HarmonyOS 悬停规范的转述，未打开全文。
- 模拟器的可调尺寸设备能否模拟半开状态。
