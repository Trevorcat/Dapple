# 书本式折叠屏内屏：编辑器研究（2026-11-14）

> 状态：探索稿，未采纳。2026-11-14 评审认为两个版本都只是把手机面板缩小贴边，没有体现大屏的优势。握持与可达范围的调研部分可参考（注意其中多为估计值），布局不要照做。后续方向见交互原型画布里的“铺满加浮球”探索。


本文只讨论一个画面：书本式折叠屏（Galaxy Z Fold7 一类）完全展开、平放在手里时的编辑器。上一版 `foldables.md` 把面板放在照片下面、沿折痕把控件分成两半，负责人否决了。这一版先查证据，再从握持和触达推出版式。原型是测试里的 Flutter 部件，用的是产品自己的盘面、强度条、坞项、成像地图、分项视图和令牌，截图在 `build/ui-fold-study/`。

## 0. 结论先说

- 单手握持展开的书本式折叠屏时，手多半握在**侧边的中段**，而不是下角（第 1 节的证据和力学分析）。拇指能舒服够到的是从这一侧边向里约 60 mm 的一条弧形带，带子的中心高度就是握持的高度。
- 所以控件是一个**跟着握持走的岛**：默认在握持侧边的中段，可以沿侧边上下滑，拖到另一侧就是换手。照片占其余全部空间，并偏向离手远的一侧。
- 拇指够不到照片上的大部分地方，所以岛里有一个**镜像**（照片的小副本，绝对映射：手指在镜像上的位置就是照片上的位置）。局部的手柄、点选、祛斑、画笔、裁切角都可以在镜像上做。按住镜像 = 按住照片 = 对比。另一只手（或另一只手的食指）照旧可以直接在照片上操作，两种做法的含义完全一样。
- 做了两个变体：A“边岛”（紧凑卡片，坞是一行）和 B“拇指弧”（卡片远端和坞都沿拇指的弧线）。推荐 A：照片面积比 B 大约三分之一，触达一样，结构更简单。B 的形状更好看，但照片代价太大（第 6 节）。

## 1. 研究：怎么握、拇指落在哪里

证据分三种：**实测**（发表的研究测量过）、**厂商**（平台设计规范的建议）、**推断**（本文自己的估计或分析）。结论是：直接针对“展开的书本式折叠屏”的握持研究，我们没有找到。下面的几何主要靠推断，需要用真机做一次握持和触点热区的测试来校准（第 9 节问题 1）。

### 1.2 握持：找到的证据

1. **实测，只有手机**：Hoober 2013 年观察了 1333 次手机使用：单手 49%，托握（一只手托、另一只手点）36%，双手 15%。他说明平板太少，没有统计。[UXmatters](http://www.uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php)
2. **实测，平板**：Wagner、Huot、Mackay，CHI 2012（BiTouch / BiPad）：预研究找到 5 种“既能托住又能操作”的握法，用户会**经常换姿势来缓解疲劳**。交互区因此放在平板的边上，配合握持的位置。拇指比其他手指快，但更累、更不稳。我们只读到摘要，没有拿到各握法的比例和高度。[摘要](https://hal.archives-ouvertes.fr/hal-00663972)
3. **实测，平板双手握**：Trudeau 等 2013（PLoS ONE）及 2018（Applied Ergonomics，8 英寸和 10 英寸平板）：靠近手掌的区域需要的拇指伸展更少；平板越大，前臂肌肉负担越大。只读到摘要。[PLoS ONE](https://dx.doi.org/10.1371%2Fjournal.pone.0067525)
4. **实测，二手引用**：Odell 与 Chandrasekaran 2012：双手横握平板时，屏幕中央很难够到。我们没读到原文。
5. **实测，模型**：Bergstrom-Lehtovirta 与 Oulasvirta，CHI 2014：拇指的“功能区”由设备尺寸、手的大小和食指在背面的位置决定。这是给手机尺寸建的模型，没有给出毫米半径。[dblp](https://dblp.dagstuhl.de/rec/conf/chi/Bergstrom-LehtovirtaO14.html)
6. **厂商**：三星 One UI 折叠屏指南，Flex 模式（半折）：内容在上半，控件在平放的下半；“不要把可交互元素放在屏幕中间的折痕附近”。没有毫米数，也不是平展状态。[Samsung Developer](https://developer.samsung.com/one-ui/largescreen-and-foldable/designing_for_foldable.html)
7. **厂商**：Android 折叠屏页面：半开时折痕附近的控件不好操作；不要把对话框和菜单压在折痕上。没有人体工学数字。[developer.android.com](https://developer.android.com/develop/ui/compose/layouts/adaptive/foldables/learn-about-foldables)
8. **厂商**：HarmonyOS 的展开态“热区”页面我们没取到（返回 503），没有可以引用的数字。能确认的有两点。一是本指南 15.6 已经采用的悬停态间距（铰链外可操作内容距铰链 ≥ 40，照片距铰链 ≥ 16），它适用于半折，不是平展。二是 HarmonyOS 有“握持手检测”能力，可以识别左手、右手、双手或未握持，用来调整单手布局。后者只有第三方开发文章提到，需要以官方文档为准。[第三方文章](https://harmonyosdev.csdn.net/693c02be0800f3458b81c949.html)
9. **没找到**：折叠屏展开态的握持比例、握持手的高度、拇指可达半径的毫米数、拇指长度的百分位数据。

### 1.3 握持：推断

展开的 Fold7 宽 143 mm、重 215 g，比 iPad mini（约 135 mm 宽，约 290 g）略窄、略轻。常见的握法（推断，和负责人自己的使用描述一致）：

| 握法 | 怎么拿 | 拇指或手指落在哪 |
|---|---|---|
| G1 单手握侧边中段 | 四指在背面撑住两半，拇指在正面 | 拇指根在侧边外约 15 mm，**高度在中段或略低**；能舒服够到的是从侧边向里的一条弧形带 |
| G2 双手握两侧中段 | 两手各握一侧，四指在背面 | 两条对称的带；屏幕正中（折痕附近）两边都够不到 |
| G3 托握 | 一只手托着背面（或下边），另一只手的食指点 | 食指哪里都能到；托着的手不操作 |
| G4 放在桌上或腿上 | 不握 | 同 G3 |

为什么是中段而不是下角（推断，力学）：设备直立时，重力对握持点的力矩只取决于重心到握持点的**水平**距离（约 70 mm），和握得高低无关。但手机总是往后倾的，这时四指在背面要同时托住上下两部分；握在下角时，上半部分全靠手腕撑着，翻倒的力矩大得多。所以单手会自然往中段走。下角握法是手机的习惯，对一块 143 × 158 mm 的板不成立。Wagner 等观察到“经常换姿势”，所以岛不能钉死在一个高度。

### 1.4 拇指触达（估计）

- 拇指根（腕掌关节）在屏幕边外约 **15 mm**。
- 舒服的带：距拇指根 **30–75 mm**，换算到屏上，大致是从侧边向里 15–60 mm。
- 最远能到：距拇指根约 **90 mm**，即侧边向里约 75 mm。
- 依据（推断）：单手握手机（约 71 mm 宽）的人能横跨整个屏宽，只是远端上角吃力，说明从拇指根算起约 85–90 mm 是吃力的极限。离拇指根太近（< 30 mm）要把拇指折回去，也不舒服，所以侧边以内约 5 mm 留空。这个空带正好就是拇指根和手掌所在的地方，放东西也会被挡住。
- 换算：Fold7 内屏 1 mm ≈ 7.24 dp，所以舒服带是 217–543 dp（从拇指根算），最远 651 dp。

### 1.5 眼睛在哪里、每个操作需要什么

眼睛在照片上，而不在手上。所以读数和反馈放在照片上缘（15.2.5 的瞬时读数），岛里只放要触摸的东西。

| 操作 | 需要什么 | 单手（G1）时的问题 |
|---|---|---|
| 盘面、强度条、坞、分项、撤销 | 拖动或轻点，相对小的区域 | 都能放进舒服带 |
| 按住对比 | 按在照片上 | 照片大部分不在拇指范围内 |
| 缩放、平移 | 双指或双击 | 单手做不了双指 |
| 局部手柄、点选、画笔、祛斑 | 精确地点在照片的某处 | 照片的远端够不到 |
| 裁切角、拉直 | 四个角和一把尺子 | 远处的两个角够不到 |
| 选成像 | 一张地图，点选 | 只要地图在岛里就行 |

## 2. 设计原则（修订后的命题）

1. **可见和可触分开设计。** 照片得到全部的可见空间；所有操作集中在一个按拇指尺寸做的岛里。
2. **岛跟着握持走。** 默认在握持侧边的中段（屏高 56%，略低于中线）。拖动岛顶的抓手可以沿侧边上下滑；拖过折痕放到另一侧，就是明确的换手。被动推断（`handedness.dart` 记录的触点位置；Android 或 HarmonyOS 能提供握持传感时也用上）只在空闲时调整默认高度和侧别，交互进行中从不移动（15.1-7）。
3. **侧边内留出手掌带。** 岛的外缘离屏幕边 32–56 dp（约 5–8 mm），那里是拇指根和手掌，放了东西也会被挡住、被误触。
4. **一只手完整，两只手只是更快。** 另一侧中段有一个小簇（撤销、重做，第二根强度条），只在检测到双手时出现；这里的东西岛里都有。
5. **含义和手机完全相同。** 按住照片（或它的镜像）= 对比；再点已选中的 = 动作卡；强度条、分项、加 / 减开关的意思不变。改的只是位置和尺寸（指南第 0 节）。
6. **照片偏向远离手的一侧，并和岛共用一条水平轴**（握持高度）。照片可以越过折痕，控件不放在折痕上。

## 3. 遥控：拇指够不到照片时怎么办

核心部件是**镜像**：岛里的照片小副本，在需要碰照片的分类（局部、裁切、放大后）里出现。它是**绝对映射**：手指在镜像上的位置就是照片上的那个点，所以没有违背 15.1-1“所见即所触”。被否决的相对映射之所以失败，是因为手指和值脱节；这里手指压着的就是照片本身，只是缩小了。照片上同时画出对应的大号手柄和光标，眼睛看大图，手在小图上。

| 操作 | 拇指在岛里怎么做 | 另一只手 / 食指 | 含义是否和手机一样 |
|---|---|---|---|
| 按住对比 | 按住镜像 380 ms 不动（没有镜像的分类：按住照片露在舒服带里的那一部分，见 G2 截图） | 按住照片 | 一样：按住照片本身就是对比；界面上仍然没有“对比”按钮 |
| 缩放、平移 | 镜像上双击 = 在那一点放大到 100% 或回到适合；放大后镜像上出现视口框，拖框 = 平移；镜像本身不缩放 | 照片上双指 | 一样（双击缩放、双指缩放平移） |
| 局部手柄 | 在镜像上拖手柄；照片上的同一手柄高亮并放大（截图 `*_local`） | 照片上拖 | 一样 |
| 点选（AI 区域） | 在镜像上点；照片上那一点闪一下 | 照片上点 | 一样，[+|−] 开关在工具条左端 |
| 画笔 | 在镜像上涂；要精细就先在镜像上双击放大，镜像跟着显示放大后的视口，精度随之提高 | 照片上涂 | 一样（移动 8 dp 才落墨） |
| 祛斑 | 先放大，再在镜像上点 | 照片上点 | 一样 |
| 裁切角 | 拖镜像上的四个角；比例芯片和拉直尺在镜像下面 | 照片上拖角 | 一样 |
| 成像 | 成像地图放在岛里，和盘面同一个位置 | 同 | 一样 |

镜像的精度（推断）：A 里横图的镜像宽 304 dp，照片宽 576 dp，约 1:1.9。指尖误差约 2 mm 时，照片上的误差约 4 mm，选区域中心、拖渐变够用；祛斑和细画笔需要先放大。竖图的镜像只有约 127 dp 宽，是目前最弱的地方（第 7 节）。

## 4. 变体 A：边岛（推荐）

一张紧凑的卡片，在握持侧边的中段：抓手、页眉（标题、读数、复位、分项）、盘面加强度条，下面是坞（一行六项），上面是撤销 / 重做。强度条放在盘面的远侧，拇指不用折回根部去拖它。镜像、成像地图、分项视图都在卡片里替换身体，卡片高度跟着内容（15.1-7）。

## 5. 变体 B：拇指弧

卡片的远侧被一段以拇指根为圆心的弧切开，坞和撤销 / 重做排在紧贴这段弧外侧的玻璃带上，同心。所有坞项到拇指根的距离相等（约 70 mm，舒服带的外缘，只用来轻点）；盘面在约 50 mm 处，最适合拖动。

## 6. 比较与推荐

| | A 边岛 | B 拇指弧 |
|---|---|---|
| 照片列宽（Fold7，单手） | 576 dp | 496 dp |
| 横图面积 | 576 × 384 | 496 × 331（**少约 26%**） |
| 竖图面积 | 576 × 864 | 496 × 744（**少约 26%**） |
| 触达 | 全部在舒服带内；坞的最远一项约 68 mm | 全部在舒服带内，坞等距 |
| 形状和拇指的关系 | 只体现在位置上 | 形状本身就是拇指的弧，一眼能看出“这是给拇指的” |
| 内容高时 | 卡片长高 | 卡片的上下角被弧切掉，高内容（分项、裁切）显得局促 |
| 实现 | 现有组件直接摆放 | 弧形卡片、沿弧排列的坞，自定义绘制 |

**推荐 A**。指南第 0 节说“取舍时优先让照片得到最大的空间”，B 为形状付出了约四分之一的照片面积，触达却没有更好。从 B 吸收两点到 A：侧边内留空的手掌带；页眉和坞的尺寸按拇指的舒服带确定，而不是按屏宽。

## 7. 自评（按严格的美术指导的标准）

做了两轮“看图、挑错、修改”。下面是最终状态的问题，先说仍然弱的地方：

1. **A 看上去仍像缩小的手机面板。** 卡片加一行坞，形状语言和手机竖屏一模一样，没有体现“这是拇指的工具”。B 解决了这一点，但代价是照片面积。还没找到两全的形状。
2. **横图上下有大片空白。** 横图在 576 dp 宽的列里只有约 384 dp 高，上下各留出约 250 dp 的灰。直方图和本组胶片条已经贴到照片上下，空白小了一些，但这是“岛占一侧”的结构性代价。照片可以在空闲时放大到全宽：轻点照片进入沉浸，岛收成侧边的一个小把手。这个状态没有画出来。
3. **竖图的镜像太小。** 竖图在 A 里的镜像约 127 × 190 dp，拖手柄还行，画笔和祛斑要先放大。可以让局部的盘面在拖手柄时让位给镜像（交互结束后才换，不在拖动中重排）。
4. **撤销 / 重做的胶囊和卡片是分开的两个东西**，视觉上像漂在卡片上方。合进坞会让坞超过舒服带的宽度，合进页眉会超过页眉三个按钮的上限（U6）。
5. **B 的玻璃带在浅灰舞台上对比偏弱**，坞项文字小（11），沿弧排开以后显得稀疏。
6. **双手模式里第二根强度条和岛里的那根同时存在**，一个值出现在两处。规则允许（另一侧小簇只是加速），但屏幕上看是重复的。
7. 截图里的读数、区域、裁切框是原型画的，像素和产品不完全一样；盘面、强度条、坞项、成像地图、分项视图、页眉是产品自己的部件。

做得好的地方：照片和岛共用握持高度那一条水平轴，构图是“一大一小”的不对称平衡，不是两个互不相干的块；读数在照片上缘，眼睛不用离开照片；所有可触的东西都在舒服带里，触达图可以直接对照。

## 8. 放到其他设备上

**(a) 宽折叠内屏**（Fold8：7.6 英寸，约 154 × 116 mm 有效显示，横向宽于高；按密度 2.625 假设为 933 × 704 dp）。原则不变：岛在握持侧边的中段，照片占其余。这块屏更矮，舒服带的上下范围（±35 mm，约 ±210 dp）几乎就是整个屏高，所以岛在竖直方向基本不用滑，只需要分左右。横图照片列宽约 520 dp，比书本式更窄。这个设备双手横握的比例可能更高（推断，宽、矮、轻，像游戏机），所以双手小簇值得默认开着。截图：`build/ui-fold-study/wide/inner_rail_light.png`、`wide/inner_rail_light_reach.png`。

**(b) 宽折叠外屏**（1248 × 1972 px，5.5 英寸，约 75 × 118 mm；按 2.625 假设为 475 × 751 dp）。这是一部“矮而宽的手机”：单手的拇指能横跨整个宽度，岛和镜像都不需要，直接用手机竖屏的版式（照片在上，面板在下，坞在底）。和普通手机不同的只有一点：高度短，面板要占约 45% 的屏高，照片区只剩约三分之一。所以面板应优先只显示一层（盘面层），分项和复杂编辑器建议引导到展开后再做，而不是在外屏上把面板拉高。截图是产品现在的手机版式直接放在这个尺寸上：`build/ui-fold-study/wide/cover_product_light.png`。

## 9. 给负责人的问题

1. **你自己的握持高度。** 单手拿展开的折叠屏时，手大约握在侧边的哪个高度？最好在真机上录一次：把我们的触点日志（`handedness.dart` 记录的落点）导出来，画成热区。这是本研究最缺的数据。
2. **镜像能不能接受？** 它是“在小图上直接操作大图”。如果你觉得眼睛和手分离太远，替代方案是：单手时局部和裁切一律先放大，再在照片靠近拇指的那一半里操作。
3. **A 和 B 选哪个？** A 的照片大约三分之一，B 的形状更有“为拇指而做”的感觉。还是要求继续找一个兼得的形状？
4. **双手小簇**放撤销 / 重做和第二根强度条，够不够？要不要把盘面也复制一份（那样就真成了“两边都有面板”）？
5. **横图的空白**：空闲时让照片放大到全宽、岛收成把手，这个默认行为你是否接受？还是希望岛永远在？
