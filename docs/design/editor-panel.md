# 编辑器控制面板（Docked Panel，照片下方或照片一侧）

版本 0.5（2026-11-12）。范围：**所有屏幕**。控制面板按屏幕尺寸、照片宽高比和当前控件，在“照片下方”和“照片一侧（侧窗格）”之间自适应；浮动窗口已全部删除。代码：`app/lib/editor/panel_layout.dart`（两种布局的纯几何求解）、`app/lib/screens/editor/dock_panel.dart`（面板、尺子、侧窗格芯片网格）、`control_pad.dart`（2D 垫板）、`editor_page.dart`（布局选择、动画、照片避让）、`editor_controller.dart`。测试：`app/test/editor_panel_test.dart`、`app/test/editor/panel_layout_test.dart`、`app/test/editor_film_test.dart`。

## 1. 为什么改（负责人的三条意见）

1. **调色盘（色板 / 色轮）太小，拖动和窗口纵向滚动冲突。** 旧窗口里的调色盘只有 72 dp 见方，且放在一个 `SingleChildScrollView` 里，手指一竖向动就在滚窗口。新设计里 2D 控件占满面板宽度、占满可用高度（至少屏宽的 40 %，竖屏 3:4 照片下约 166 dp，横幅照片下 250 dp 以上），周围没有任何滚动视图；表面自己在手势竞技场里立即胜出（`ClaimPanRecognizer`），所以浮动窗口里的调色盘也不会再被滚动抢走。
2. **窗口盖住照片，而屏幕上下明明有大片非照片区域。** 面板不再浮在照片上，而是占照片之下、分类坞之上的空地：照片先按自身宽高比放进“顶栏下沿 ～ 面板上沿”之间，面板拿走照片留下的空位；空位不够控件用时，照片区域（动画）缩小，而不是被盖住。竖屏 3:4 照片留下约 200 dp，横幅 3:2 照片留下 450 dp 以上（用来放大调色盘、直方图）。
3. **选行后要到窗口外的照片上拖动改值，眼睛和手指分离。** 每个想法单独都成立（全局拖动改值；二级菜单），合在一起就割裂。症结在“二级菜单”这一层：它只负责选，不负责改。现在二级菜单（芯片条）下面紧跟**一把全宽尺子**，在眼睛所在的位置直接拖；拖动照片仍然可用（次要手势），两者共用同一条代码路径（`EditorController.adjustBegin` / `adjustMove` / `adjustEnd`，`editTick`，`engine.beginInteraction(activeParam)`），所以任一方向拖，另一边的尺子、芯片读数同步变化。

## 2. 布局

```
顶栏（返回 / 撤销重做 / 保存）
┌───────────────────────────────┐
│            照片                │  先按宽高比放入 [顶栏下沿 + 8, 面板上沿 - 8]
└───────────────────────────────┘
┌ 面板 ─────────────────────────┐  左右 12 dp 边距，圆角 20 dp，不盖照片
│ ▁▁ 抓手 (24 dp)                │
│ [↺] ［曝光 +0.6 EV］ 对比度 … │  芯片条（56 dp，横向滚动，选中项居中）
│        +0.60 EV      [↺]      │  数值行（44 dp，点数值 = 键入）
│ ───────|─────────────────────  │  全宽尺子（64 dp）
└───────────────────────────────┘
分类坞（光线 颜色 风格 裁切 效果 更多），不变
```

- **高度规则（面板贴合内容）**：面板高 = 芯片条 + 当前参数的控件所需高度，不留空白；照片留下的多余高度全部给照片区域，照片在“顶栏下沿 ～ 面板上沿”之间**垂直居中**（多出的空间上下均分）。只有两样东西可以吃掉多余高度：2D 垫板（最高到正方形）和尺子下的宽直方图（最高 120 dp，余量不足 70 dp 时改用数值行里的小直方图）。控件放不下时照片区域缩小，而不是面板盖住照片。换参数、换分类时面板高度用临界阻尼弹簧（`SpringTier.medium.opacity`）过渡，无过冲。
- **照片避让的实现**：照片视图自己的缩放数学要求画面居中，因此在整个照片视图外加一层非对称 `Padding`（顶栏之下、面板之上）；缩放时照片也被裁在这个区域内，不会钻到面板下面。
- **折叠**：抓手（点击，或上下划）把面板折成“抓手 + 芯片条”（80 dp），照片取最大空间；折叠时点芯片会自动展开。点照片空白处同样折叠 / 展开（沿用旧行为）。
- **返回键顺序**：数值输入 → 折叠面板 → 关闭面板 → 退出页面。
- **键盘**：数值输入时面板整体上移到键盘之上，照片相应缩小。
- **手性**：全部控件在屏幕下部 40 % 内；分类“复位”钮放在拇指的**远端**（右手在左、左手在右），渐隐覆盖在芯片条端点，不占宽度；2D 垫板的“精细”开关放在垫板的拇指侧上角。所有点击目标 >= 44 dp 高（芯片 48 dp）。
- **亮 / 暗**：只用既有令牌（`surface`、`chip`、`accentSoft`、`accent`、`track`、`sep`），随系统切换。界面里没有说明文字。

## 3. 面板内容

两层，面板内没有纵向滚动。

**上层：芯片条。** 每个参数一个按内容定宽的芯片（两行：名称 + 当前值，约 64–132 dp 宽，手机上同时能看到 4–5 个，高 48 dp）；已改动的名称、数值着强调色并带右上角小圆点；选中项高亮并居中。每个芯片都显示数值，选中的也不例外（真机上选中芯片没有数值读起来不对）；尺子上方的大数字照旧保留。点未选中的芯片立即选中（无双击延迟）；双击选中的芯片、或点数值行右侧的小复位钮，复位该参数；尺子上双击同样复位。动作类的行（旋转、翻转）是点一下就执行的芯片。

**下层：选中参数的唯一一个大控件。**

| 参数类型 | 下层 |
|---|---|
| 一维数值（曝光、对比度、强度……） | 数值行 + 全宽尺子（刻度随值滚动，指针固定在中央，“自动”位有标记；缓存的刻度标签；档位触感、速度增益、精度档沿用拖动照片的同一套映射——手指上移得到“精细 / 极细”）。点数值进入键入，EV 仍按 EV 键入。 |
| 二维（调色盘、色轮、曲线点） | 垫板：全面板宽、占满剩余高度、至少屏宽 40 %。读数在该参数的芯片里。曲线：竖拖改选中点，点一下选最近的点。 |
| 明暗目标（3×3） | 放大的 3×3 格（格边最大 64 dp），点选。 |
| 离散（色范围、通道、区域、裁切比例、风格） | 对应的选择条（色范围圆点、风格色块条、其余为横向滚动的文字芯片）。 |

**风格（含胶片）。** 芯片条含全部风格行；选中的行属于胶片族（胶片、相纸、胶片强度、颗粒、光晕……）时，芯片条**下方**出现胶片色块条，再往下是该行的尺子（相纸则是相纸条）。**与需求稿的差异**：需求稿写“用色块条替换芯片条”；实现保留芯片条在原位，把色块条放在它下面。原因：芯片条若被替换，点一下“胶片强度”芯片后，芯片自己就跑了，手指下面的目标会移动，也没有回到“风格 / 调色盘”的入口。

**直方图。** 光线 / 曲线 / 风格：面板高度够（横幅照片）时，在尺子下画一条宽直方图；不够时，在数值行左侧放原来的 96×32 小直方图。**不再**在照片上盖读数浮层：拖动时数值在芯片和数值行里，照片上只保留“原片”提示和“n / N”计数。

## 4. 与旧手势系统的关系

- 拖照片仍然改选中的参数（水平）、竖拖切换芯片，长按看原片，双指缩放——这些不变，由 `EditorGestureSurface` + `GestureArbiter` 处理。
- 尺子和垫板不经过仲裁器，而是自己用一个 `ClaimPanRecognizer` 立即占住指针，超过 3 dp 后调用 `EditorController.beginOn(row, axis, …)`，再喂 `adjustMove`；`beginOn` 先把该行设为分类的活动行并聚焦，然后走 `adjustBegin`。一次手势 = 一个撤销步。
- 性能：面板只在结构性变化（选择、一次拖动的第一步、撤销）时重建；拖动中，尺子、垫板、被选芯片的数值各自监听 `readout` / `edits` 通知重绘，外层有 `RepaintBoundary`；刻度标签的 `TextPainter` 按“文字 + 颜色”缓存；拖动期间面板不整体重建。

## 5. 胶片的两块垫板与宽容度（v0.4）

风格里选了胶片后，芯片条里 `胶片强度` 之后是：

| 芯片 | 控件 | 参数键（params 表，归一化，范围 [-1, +1]，0 = 自动） |
|---|---|---|
| 曝光 | 2D 垫板：X 拍摄曝光（左欠曝 ↔ 右过曝），Y 冲印深浅（下深 ↔ 上浅） | `film_shoot`（X，+1 = 过曝）、`film_print`（Y，+1 = 浅） |
| 质感 | 2D 垫板：X 白平衡（**单边**：默认在左边缘，左 数码 → 右 胶片，范围 0..1，没有负半边），Y 黑位（下 抬黑 ↔ 上 压黑，中线为自动） | `film_wb`（X，0 = 数码白平衡，1 = 胶片白平衡：胶片自己的白平衡看到真实的光）、`film_black`（Y，+1 = 压黑，-1 = 抬黑，0 = 纸的真黑） |
| 宽容度 | 尺子，按百分比显示：-1 / 0 / +1 = 55 / 80 / 98 %（分段线性，80 % 为自动） | `film_latitude` |

垫板的自动位置画一个圆环和“自动”字样（曝光垫板在中心，质感垫板在左边缘中点），磁吸（沿用调色盘的映射，0..1 范围），双击复位两轴；读数（`+18 +11`，自动时为“自动”）在芯片里；四个边缘有方向字（欠曝 / 过曝 / 深 / 浅；数码 / 胶片 / 抬黑 / 压黑）。引擎若报告场景色温和胶片参考色温（`scene_k` / `stock_k`），它们作为小字显示在质感垫板左右两端（如 4600K / 5500K），缺省则不显示。选中垫板时胶片色块条隐藏（垫板需要空间），各芯片只显示自己的控件：胶片色块条是“胶片”芯片的控件（和芯片条之间留 12 dp 空隙），不再叠在其他芯片的尺子上方。旧的 `胶片曝光`（`film_exp`）滑杆从界面移除，字段和规格保留，旧编辑仍会下发。`无` 清胶片时一并清掉这五个键（`filmValueKeys`，现为 `film_shoot`、`film_print`、`film_black`、`film_wb`、`film_latitude`；`film_cast` 已移除，旧存档里的该键在读取时丢弃）。

### 有效范围（引擎的 `dapple_session_film_pad_json`）

一个轴的某一端如果对当前照片和胶片不改变渲染（例如反转片没有冲印：`film_print` +1 无效；场景光已和胶片平衡一致时 `film_wb` 无效），那一端**不可达**：

- 半边失效：垫板保留，失效的那一半画成斜线阴影并变暗，光标停在中线，进不去（映射器 `PaletteMapper` 的单轴上下限）。
- 一整根轴失效：垫板变成剩下那根轴的单轴尺子（尺子范围同样不含失效端，例如只剩 0..+100）。`film_wb` 是单边轴，只有它的 +1 端有意义：`effective_hi` 为 false（场景光已经和胶片的平衡一致）即整根轴失效，质感退回黑位尺子。
- `film_latitude`（宽容度）也有 `effective_lo` / `effective_hi`：两端都失效则隐藏该芯片，只有一端有效则尺子只到有效的一侧。
- 两根轴都失效：隐藏该芯片。
- 刷新：照片、胶片（含相纸）或 `film_shoot` 变化后去抖 300 ms，在后台 isolate 里查询，拖动期间不查（抬手后再查）；引擎答不上来、没有该符号或答非所问时一律当作“全部有效”。

期望的引擎 JSON（所有字段可缺省，缺省 = 有效；`ok:false` 也当作全部有效）：

```json
{"ok":true, "...现有字段...",
 "effective_lo": {"film_shoot":true, "film_print":true, "film_black":true, "film_wb":true, "film_latitude":true},
 "effective_hi": {"film_shoot":true, "film_print":false, "film_black":true, "film_wb":false, "film_latitude":true},
 "scene_k": 4600, "stock_k": 5500}
```

`effective_lo` 是该键取 -1 时渲染是否有变化，`effective_hi` 是取 +1。也接受逐键对象形式 `{"film_print":{"effective_lo":true,"effective_hi":false}}`。Dart 侧：`lib/model/film_pad.dart`（`FilmPadRanges.parse`，容错），`DappleSession.filmPadJson`（可选符号 `dapple_session_film_pad_json(session, params_json)`，参数是当前照片的编辑 JSON），`EditorController.filmRanges`（可注入假实现做测试）。

**原生接入**：引擎从编辑 JSON 里把 `film_shoot`、`film_print`、`film_black`、`film_wb`、`film_latitude` 读成普通浮点，缺省 = 0；它们随 `EditState.toWire` 和其他 `film_*` 键一起下发（有胶片时才下发，0 时不下发）。垫板的写入点只有 `EditorController._moveTwoD` 的 `TwoD.offset` 分支（`NATIVE BINDING` 注释）；规格在 `model/params.dart`。拖动时 `engine.beginInteraction(activeParam: ...)` 对垫板传 X 键（`film_shoot` / `film_wb`），对尺子传各自的键。

## 6. 自适应布局：照片下方或照片一侧

对当前屏幕、照片宽高比和所选控件，同时算出两种布局，取**照片更大**的那个（侧窗格要大 8 % 以上才算赢，避免在边界上来回跳）：

- **下方（bottom）**：照片放在顶栏和面板之间，面板在分类坞上方（高屏手机）。
- **一侧（side）**：面板是贴在拇指一侧的窄窗格（按 `settings.handSide`：右手在右边缘，左手在左边缘），宽 = 屏宽的 36 %，限制在 300 到 400 dp；分类坞在窗格底部；顶栏只占照片这一列；照片放进剩下的区域（左右各留 16 dp）。
- 结果（`test/editor/panel_layout_test.dart` 的矩阵）：N5 外屏、iPhone 式 440×956、360×780、360×640 一律在下方；横持手机（951×414）一律在一侧；展开的内屏（817×902）竖构图（9:16、2:3、3:4）在一侧、横构图在下方；平板（1280×800）除 3:1 外在一侧。照片从不被盖住，照片尺寸和规则一致（测试容差 3 dp）。
- **稳定性**：布局按“分类里最高的那个控件”决定（`panelNeeds(groupLevel: true)`），缓存键是（分类、屏幕尺寸、照片宽高比、手性、照片）；拖动中不重新决定，换参数不会翻转，换分类、换照片、旋转或折叠、改手性时重新决定，并用同一个弹簧动画过渡（照片区域、面板、分类坞三个矩形一起插值）。
- **面板高度**：不低于一把尺子的高度（所以同一分类里尺子、选择条之间换参数，面板和照片都不动），遇到更高的控件（大垫板、明暗 3×3）才长高；尺子在带直方图的分类里多出的高度给宽直方图（上限 120 dp），选择条不吃这份高度（否则会漂在空白里）。面板里任何状态都不留超过约 24 dp 的空白带（测试逐控件量过）。照片即垫板时，面板只是芯片条加一行细提示，**垫板和明暗格的高度都不算**，照片拿回全部空间（N5 外屏 2:3 照片测试：边长不小于无面板时的 95 %）。代价：从尺子换到垫板时面板会长高、照片跟着动画变小。
- **侧窗格内容**：窗格顶部是页眉（分类图标和名称，分类复位钮在自己的格子里，不压芯片），其下（空间够且当前不是垫板时）是直方图（上方的空列不再是死的），再下是 2 或 3 列芯片网格（只显示整行，放不下的行在网格里自己竖向滚动，两端有渐隐作为滚动提示；选中的芯片自动滚入视野），最下面是占满窗格宽度的尺子（直方图已在上面，尺子下不再重复）或占满窗格宽度、不必是正方形的垫板，窗格贴着分类坞（底部对齐，拇指够得到）。折叠时只剩页眉和芯片网格。
- **照片即垫板**（photo as pad）：显示大 2D 垫板会让照片边长低于不带面板时的 80 %（两种布局都试），就不显示大垫板：只留芯片条加一行细提示（轴向文字、读数、复位），在照片上拖动同时驱动两个轴，拖动时照片上方出现小读数，芯片显示数值。能放得下时照旧显示大垫板。滑杆不受影响。该判断在分类级别做，同一分类里要么所有垫板都是大的，要么都用照片。
- **折叠 / 返回键 / 手性 / 大字号 / 暗色**在两种布局里都保持：返回键顺序仍是 数值输入 → 折叠 → 关闭 → 离开；折叠与展开（外屏 414×951 与内屏 817×902 之间）会带着选中的参数和编辑状态过渡，布局从下方动画到一侧。
- **删除的东西**：浮动窗口、第二个窗口、直方图窗口、避让位移、窗口位置记忆（`settings.editorLayout` 字段还在，设置页的“重置”仍会清它，但不再有人读）；`WindowManager` 只剩“打开哪个分类、是否折叠、手性”。
- **调试入口**（仅 debug 构建）：往应用外部文件目录推 `debug_open.json`（见 `lib/services/debug_open.dart`）即可打开指定照片、分类、参数、折叠状态和胶片，截图不再依赖盲点。

手性：新装的默认是右手（`settings.handSide` 默认 1 = 右）：窗格在右（拇指）边缘。设置在 设置 页的 手性 分段（自动 / 左手 / 右手，`settings.handedness` 0 / 1 / 2）；“自动”会按手势推断并写入 `settings.handSide`。模拟器上窗格在左边，是因为我的合成滑动被推断成了左手。

“预览”标签在所有布局里都在照片的前导（左上）角内侧，8 dp。

## 7. 待负责人确认的问题

1. **尺子方向。** 现在手指向右 = 数值增加（和拖照片一致，像滑杆的拇指）。另一种是“内容跟手”（手指向右 = 刻度向右 = 数值减小，像 iOS 照片的拨盘）。哪种更符合直觉？
2. **同一分类内面板高度恒定**换来的空白：风格里选择条、尺子比调色盘矮，面板里有空。是否改成“只在选择条这类矮控件上缩小，换回垫板时再长高”（照片会跳一下）？
2b. **侧窗格贴底**：窗格和分类坞靠在底部（拇指够得到），上方是空的舞台；是否改成窗格铺满整列（和设计稿一致）？
3. **风格里芯片很多**（最多 13 个）。是否把“风格 / 调色盘 / 明暗”与“胶片”拆成两组（二级分段），还是维持一条横滑的芯片？
4. **点照片空白处折叠面板**是沿用旧行为，容易误触；是否取消，只留抓手？
5. **调色盘相对映射。** 垫板仍用相对映射（慢速时光标走得比手指慢，快甩时更快），大垫板上光标不会贴手指。是否改为“绝对跟手 + 长按精细”？
6. **颜色分类里没有调色盘**（调色盘在“风格”，色轮在 更多 > 分级）。如果希望颜色分类也有一块大调色盘，需要改参数目录，不是本次范围。

## 8. 已知粗糙之处

- 尺子的刻度标签在测试字体下显示为方块（测试环境字体），真机字体正常；大字号（1.6×）下芯片条自动增高，已测无溢出。
- 面板与照片的高度变化同步用弹簧动画，动画期间引擎会收到逐帧的视口更新（短暂，约 0.4 s）。
