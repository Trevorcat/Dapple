版本 0.1（2026-11-14），待负责人定。起因：负责人否掉了现在的局部面板（选中区域后是强度条 + 光线盘 + 颜色盘两块半宽盘面并排，`build/ui-pages/phone-portrait-412x915/44_local_circle.png`、`47_local_brush.png`），原话：“不好看，设计非常粗暴，没有因地制宜，粗暴的堆两个调色盘也不合理，没有做第一性原理分析以及用户真正要做的是什么。”
原型（只在测试里，不进 app/lib）：`app/test/proto/local_redesign/`，截图：`build/ui-local-redesign/<方案>/<屏幕>_<状态>.png`。重新出图：`flutter test test/proto/local_redesign/local_redesign_test.dart --dart-define=PROTO=true`。

## 1. 第一性原理

### 1.1 用户脑子里的那句话

调局部的时候，用户心里几乎总是**一个区域 + 一个方向**的短句：

| 心里的话 | 区域 | 实际要的改变 |
|---|---|---|
| 脸亮一点 | 人 / 脸 | 提亮（曝光 +，阴影 +） |
| 天压暗 / 天太亮了 | 天空、上半部分 | 压暗（曝光 −，高光 −） |
| 背景别抢眼 | 背景、边缘 | 变暗一点、淡一点、软一点（“弱化”） |
| 让它跳出来 | 主体 | 稍亮、更浓、更清楚（“突出”） |
| 这里暖一点 / 冷一点 | 夕阳、阴影里的雪 | 色温 ± |
| 这里清楚一点 / 柔一点 | 主体 / 皮肤、远景 | 清晰度、纹理 ± |

这些句子有三个共同点：**一维**（一个方向，只问“多少”），**单向**（压暗的人不会同时想提亮），**结果说了算**（看照片，不看控件）。一句话里有两个改变（“天压暗再冷一点”）的时候，也是两件先后做的事，不是一个二维动作。

### 1.2 眼睛在哪里

眼睛在照片上那块区域里，不在面板上。所以面板控件要**闭着眼也能用**：大的命中区、位置固定、手指移动和变化方向一一对应（往上 = 更多）。二维盘面要求手指同时管两个方向，眼睛得回到盘面上确认光标在哪；一根竖条只有一个方向，拇指找得到就行。

### 1.3 各种局部调整有多常用

没有找到公开的使用量统计（检索到的都是教程和厂商文档），所以下面的频率排序是**我的判断**，依据是几个成熟产品把哪些东西放在最前面：

- 暗房传统：局部调整首先是“遮挡和加光”（dodge and burn），也就是只改明暗（Ansel Adams《The Print》；Photoshop 的 Dodge / Burn 工具同理）。
- Snapseed 的“画笔”工具一共只有四种：加光减光、曝光、色温、饱和度（[Google Snapseed 帮助](https://support.google.com/snapseed/answer/6157715)）；“局部”（控制点）只有亮度、对比度、饱和度，有的版本加结构（[Google Snapseed 帮助](https://support.google.com/snapseed/answer/6157827)），每个点一次只调一项（上下滑选项目、左右滑改值）。
- Lightroom 的自适应预设（选好区域后的一键配方）按意图命名：主体“Pop / Warm Pop / Soft / Cool Soft”、天空“Blue Drama”等、人像“Enhance Portrait”（[Adobe：自适应预设](https://www.adobe.com/learn/lightroom-cc/web/optimize-workflow-with-adaptive-presets)，[Photofocus](https://photofocus.com/software/adobe/how-to-use-adaptive-presets-in-lightroom/)）。
- 教程里最常见的渐变用法是压暗天空（[DIYPhotography](https://www.diyphotography.net/?p=309171)）；常见的建议是先在区域里做明暗，再做色温 / 饱和度（[Michael Frye 的局部调整框架](https://education.michaelfrye.com/?p=8574)）。

由此得出的排序：**明暗（约过半） > 色温 > 浓淡 / “突出、弱化” > 清晰 / 柔和 > 其余（色偏、白黑色阶、去雾、降噪）**。前四类加起来占绝大多数。

### 1.4 引擎给每个区域的是什么

`app/lib/model/local_adjust.dart` 与 `docs/engine/pipeline-architecture.md` 40.1 / 40.2：每个区域 `{on, strength 0..100, invert, mask, adjust}`，`adjust` 的参数（JSON 单位）：

| 组 | 参数与范围 | 在流水线里的位置 |
|---|---|---|
| 光线 | `exposure` −80..80（= EV × 20，±4 EV），`contrast`、`highlights`、`shadows`、`whites`、`blacks` −100..100 | 场景线性，`LocalLinear`（像在暗房里加光减光，之后照常走全局色调和胶片） |
| 颜色 | `temp`、`tint`、`saturation`、`vibrance` −100..100；`color_hue` 0..360 + `color_sat` 0..100（v1 不露出） | 同上 |
| 质地 | `clarity`、`texture`、`sharpen`、`dehaze` −100..100，`noise` 0..100 | 显示域窗口，`LocalDetail` |
| 人像 | `smooth`、`even`、`redness`、`undereye`、`shine`、`facelight`、`whiten`、`heal` 0..100 | 第 43 节 |

现在的配方（`local_pad.dart`）只用了 `exposure / contrast / whites / blacks / temp / saturation / vibrance`：**质地这一组在默认层完全没有**，而“这里清楚一点 / 柔一点”是常见的话。

### 1.5 两块半宽盘面错在哪

1. **精度减半**：两块盘面各约 150 dp 宽，一个手指的位移对应的变化是全局盘面的两倍；局部要的恰恰是“一点点”。
2. **注意力分裂**：两个光标、两套四边图标，眼睛要在两块之间找“我现在动的是哪一块”。
3. **大部分时候一块闲着**：按 1.3 的频率，多数区域只动明暗；颜色盘常年在中心，却占着一半面积。
4. **二维对不上一维的意图**：光线盘的纵轴（反差）在局部几乎没人要；“压暗”只需要横轴的一半。
5. **违反“默认是简化操作、细调在分项后面”**：人像组已经是“芯片 + 一根强度条，盘面只在分项后面”，普通区域却默认摆出两块盘面，局部里有两套逻辑。
6. **照片让出空间**：面板按盘面的舒适高度算，照片被压小（见 4.1 的尺寸表）。
7. **漏了质地**：默认层不能让一块地方更清楚或更柔。

### 1.6 什么必须和全 App 一样，什么应该因地制宜

必须一样（guidelines 第 0 节、U 规则）：强度条的含义（下 = 无、中 = 推荐 100 %、上 = 最多，U1）；「分项」 = 细节层（雷达 + 尺子）；再点已选中的芯片 = 动作卡（U3）；照片上的加 / 减开关只有一种（U2）；按住照片 = 对比（U4）；页眉 `标题 · 读数 …… 复位 · 主动作`（U6）；图标词汇（月 / 日、蓝点 / 橙点、空心 / 实心水滴、波 / 锯齿）；照片上只摆形状，不改调节量（15.1-1）。
应该适配：面板高度跟着内容走（芯片层比盘面层矮，照片拿回空间）；默认层给的是“意图”而不是参数；区域种类决定先选哪一个（第 5 节开放问题）。

## 2. 三个方案

所有截图都是同一张照片（湖面晨昏，竖屏窗口用 3:4 裁切，横屏窗口用 4:3），同一套真实组件（页眉、图标格 `DTile`、强度条 `StrengthStrip`、盘面 `PadFace`、雷达 `RadarView`、尺子 `ItemRuler`、令牌），照片上的“效果”是颜色矩阵穿过区域的蒙版，只用来看版式，不代表引擎画质。状态：1 = 刚建好区域（红色范围显示），2 = 正在调，3 = 分项，4 = 两个区域。对比基准：`0_current/*_2_using.png`（现在的两块盘面）。

### 方案 A：意图芯片 + 一根强度条（人像组的同一套做法）

截图：`build/ui-local-redesign/A_intents/`（`412x915_1_created.png` … `915x412_4_two_areas.png`）。

- **默认层**：左边一根强度条，右边 8 个意图格，两行四列、**成对排列**：`提亮 压暗 | 变暖 变冷` / `突出 弱化 | 清晰 柔和`。对内间距 8，对间间距 16，一眼看出哪两个是反义。图标全部来自盘面的现有词汇（日 / 月、橙点 / 蓝点、实心 / 空心水滴、锯齿 / 波），用户在别处见过它们。
- **用法**：点一个意图 = 打开它并选中（100 %，推荐量），强度条管这个意图的量（中 = 100 %，上 = 最多）；再点另一个 = 叠加（“压暗 + 变冷”）；同一对里另一个会被关掉（不会既提亮又压暗）。已开的格 = 淡底（U7 的“开”），正在调的 = 淡底 + 描边 + ⌄；再点它 = 动作卡（关掉 / 复位，U3）。页眉读数 `压暗 · 强度 130%`。还没选时页眉写“选一种调法”，强度条淡显（空状态就是第一步，15.8-1）。
- **配方**（纯函数，中 = 推荐、上 = 最多，起点值，要像全局配方那样在多张照片上看渲染再定）：提亮 曝光 +0.6 EV、阴影 +10（最多 +1.5 EV）；压暗 曝光 −0.6 EV、高光 −10（最多 −2 EV）；变暖 / 变冷 色温 ±20（最多 ±60）；突出 曝光 +0.2 EV、对比 +12、清晰度 +15、鲜艳度 +15；弱化 曝光 −0.2 EV、对比 −10、饱和度 −20、清晰度 −10；清晰 清晰度 +20、纹理 +15、去雾 +5；柔和 清晰度 −20、纹理 −20。区域的参数 = 所有已开意图的配方之和 + 分项偏移（同 `applyLocalUi` 的“配方 + 偏移”），引擎 `strength` 固定 100（同人像芯片）。
- **分项**：`‹ 局部 · 区域 1 · 压暗 …… 复位`，光线 / 颜色 / 质地 三组的雷达 + 一把尺子（与现在的局部分项、全局分项同一控件），打开时停在当前意图所属的组。这一层把区域芯片那一行让出来，雷达多 48 dp（`412x915_3_items.png`；‹ 回去芯片就回来）。**不放盘面**：意图已经覆盖了盘面那两个方向，盘面再出现等于第三套说法。
- **几个区域**：区域芯片一行照旧，每个区域记住自己开了哪些意图；切换区域，格子的状态跟着换（`4_two_areas`）。
- **尺寸**：默认层的身体只要两行格子（56–64 dp × 2），面板比现在矮约 100 dp；360 宽时格子 57 dp 宽，仍 ≥ 56；横屏侧窗格里四列刚好放下（对内间距收到 4，对间 8）。
- **风险**：8 个意图是否够用（例如“只压高光”）——够不着的进分项；“突出 / 弱化”是组合配方，用户可能想知道它动了什么——分项的虚线多边形就是答案；意图之间叠加后的强度条只管选中的那一个，要靠格子的“开”态看出还有别的在起作用。

### 方案 B：一块全尺寸盘面 + 三向切换

截图：`build/ui-local-redesign/B_one_pad/`。

- **默认层**：强度条（区域整体强度，引擎 `strength`）+ 一块整宽盘面；盘面上方的切换 `光线 | 颜色 | 质地`（分段控件，改过的组带一个蓝点）放在区域芯片那一行的右端，放不下时（360 宽、两个以上区域）自己占一行（`360x780_4_two_areas.png`）。
- **映射**：光线盘 = 现在的局部光线配方（曝光、反差），颜色盘 = 冷暖、浓淡，质地盘新加（柔↔锐 = 清晰度 / 纹理，干净↔颗粒 = 降噪 / 纹理）。旧编辑的 `lx ly cx cy` 原样可用，迁移最小。
- **分项**：同 A。
- **好处**：精度与全局盘面一样；三组都在；与全局分类完全同一个样子。
- **问题**：仍然是“参数轴”而不是“意图”，压暗天空要先想“这是光线”，再找“左边是暗”；二维盘面的另一个轴大多没人用；一次只看到一组，颜色和质地动了没动只能靠蓝点；默认层不是“简化操作”（负责人的规则），面板高度和现在一样，照片没拿回空间（4.1）。

### 方案 C：区域是“作用范围”，坞上的光线 / 颜色 / 质地作用在它上面

截图：`build/ui-local-redesign/C_scope/`。

- **默认层（局部）**：只管区域：芯片一行 + 三个入口格「光线 / 颜色 / 质地」（写着“未调 / 亮 30 / 暖 20”）。面板最矮，照片最大（`1_created`、`4_two_areas`）。
- **调整**：点入口格或坞上的光线 = 光线面板，但作用在区域上：页眉 `光线 [▤ 区域 1 ✕]`，照片上缘胶囊“只调 区域 1”，区域的轮廓细虚线，坞上三项各带一个区域小徽标（`2_scoped_pad`）；✕ 回到整张照片。盘面是整宽的全局盘面。
- **分项**：全局分项的雷达 + 尺子，作用在区域上（`3_items`）。
- **好处**：只有一套盘面、一套分项；区域面板极简；盘面精度最高。
- **问题（严重）**：**模式混淆**——同一个坞项一会儿改整张、一会儿改一块，读数、坞上的字形、撤销的含义都随范围变；用户去了别处再回来，不知道“光线”现在改的是什么（违反第 0 节的检验句）。360 宽的页眉放不下范围胶囊 + 读数（读数被截断，`360x780_2_scoped_pad.png`），坞上的徽标太小。人像组无法套进这个模型。局部里的大部分时间要在两个坞项之间来回跳。

### 被否掉的第四条路：在照片上拖区域本身改值

选中区域后在区域里上下拖 = 提亮 / 压暗（Snapseed 的控制点就是这样）。手指就在要改的地方，看起来最“直接”。但负责人在真机上否掉过这种相对拖动（15.1-1：照片上不做调节手势，手指和值脱节，读不出现在改的是什么），而且照片上的手势已经被形状手柄、画笔、取样、按住对比占满，冲突无法消除。不做。

## 3. 推荐：方案 A

理由：

1. **对上了用户的那句话**：格子上的字就是心里的话（“压暗”“突出”），一点一拖，一维、单向，和 1.1 完全一致；不需要先把意图翻译成参数轴。
2. **一套逻辑**：普通区域与人像组同一个做法——芯片 + 一根强度条，细节在分项后面。局部里不再有两套模型，强度条在哪里都是“这一项的量”（U1）。
3. **照片拿回空间**：同一屏幕、同一照片下照片的尺寸（`photo_sizes.txt`）：412×915：现在 334×445，A 356×475（面积 +14 %），B 334×445，C 370×493（调整时）；360×780：现在 232×310，A 255×340（+21 %），B 232×310，C 268×358。
4. **补上了质地**（清晰 / 柔和、突出 / 弱化里的清晰度），默认层就能说“这里清楚一点”。
5. **因地制宜而不打乱位置**：格子的位置固定（肌肉记忆），区域种类只决定先选中哪一个（见开放问题 1）。

A 的弱点（照实说）：

- 8 个格子是一份**编辑选择**，总有人要的不在里面（例如只动高光、只动色偏）——它们在分项里，多一步。
- “突出 / 弱化”是组合配方，单看字不知道动了哪些参数；配方幅度要在一批照片上调过才可信（本轮只看了版式）。
- 同时开几个意图时，强度条只管选中的那个，别的“开着”只靠淡底表示，用户可能忘了。
- 两行格子比盘面“轻”，喜欢自由二维拖动的用户会觉得被限制（分项能补，但不是同一种手感）。
- 横屏侧窗格里格子到了 56 dp 下限，再加字号就要换成两列四行（会比侧窗格高，需要滚动或缩小强度条）。

### 3.1 要改 app/lib 的地方（下一轮，不在本轮）

- `lib/model/local_pad.dart`：新增意图表 `localAims`（id、字、图标、对立项、配方的推荐值与最多值）与纯函数 `aimRecipe(aims) → ops`；`applyLocalUi` 的配方来源从 `lx/ly/cx/cy` 换成意图量；`localStripPercent` 对普通区域改成“选中意图的百分比”；`localReadout` 改成 `压暗 · 强度 N%`。
- `lib/model/local_adjust.dart`：`LocalUi` 加 `aims: {id: 量}` 与 `sel`（JSON 键 `aims`、`sel`），保留读旧的 `lx ly cx cy`。
- `lib/screens/editor/local_panel.dart`：`LocalBodyView` 的两块盘面换成“强度条 + 意图格”（复用 `PortraitPanel` 的布局与 `DTile`，成对间距）；`LocalItemised` 打开时停在当前意图所属的组、隐藏区域芯片行；去掉 `local-pad-light / local-pad-color`。
- `lib/screens/editor/local_controller.dart`：`tapAim`（开 / 选中 / 关对立项）、意图的动作卡（关掉、复位）；`lightPad / colorPad` 两个 PadSource 合成一个“选中意图的强度条”。
- 面板高度：局部默认层按“两行格子”报高度（同 `portraitBodyNeed`）。
- 文档：`local-adjustments.md` 第 1、3、4 节，`guidelines.md` 15.1-5（局部区域的强度条读数），文案表加 8 个意图词。
- 测试：配方纯函数（中心、上下限、夹住范围）、旧编辑打开不变（见下）、`u_rules_test` 的强度读数、截图巡检加局部默认层。

### 3.2 已存编辑的迁移

原则：**打开旧编辑，画面一个像素都不变**；只换界面上的说法。

- 引擎只看 `adjust` 和 `strength`，这两样原样保留，渲染不变。
- 界面状态：读到旧的 `ui {lx, ly, cx, cy, a, off}` 时换算成意图：`lx < 0` → 压暗、`lx > 0` → 提亮（量 = |lx| 按曝光配方折算），`cx` → 变暖 / 变冷，`cy > 0` → 突出的一部分不做猜测，留作偏移；然后令 `off = 旧 ops − 新配方(意图)`，于是 ops 完全不变（同 `localUiOf` 现在对没有界面状态的区域的做法）。
- 旧的区域 `strength ≠ 100`：保留在数据里照常下发；分项里出现一项“区域强度”（只在 ≠ 100 时出现），拖回 100 后消失。
- 没有 `ui` 的区域（别处做的、更早的版本）：没有意图打开，全部参数是偏移，页眉写“选一种调法”，分项里能看到原来的值；第一次点意图只在偏移之上加配方，不会跳。
- 人像区域不受影响（它们本来就是芯片）。
