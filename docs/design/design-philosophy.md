# 设计思想

版本 0.2（2026-11-14）。负责人与 Claude 逐节讨论后定稿。

本文不依赖任何具体项目。它只讲立场、原则和检验方法，不含颜色、尺寸、组件这类数值。各项目的设计指南引用本文，并负责把原则落成具体规则；两者冲突时，以本文的原则为准，回头修指南。

---

## 1. 立场

1. **从方法里提炼，不从符号里提炼。** 不使用纹样、书法字、青花、回纹、水墨这类“中式元素”来表明身份。元素正确而气韵缺失的拼贴，是“新中式”的通病。民族特色应通过东西本身的做法体现。
2. **实用是因，简约是果。** 把用处做到位，把多余的去掉，剩下的自然简约。简约不当作目标来追求，否则它只是另一种用来区别于他人的趣味。
3. **不说“高级”。** 评价一个设计只问两件事：它是否对得起它的用处，是否对得起用它的人。
4. **雅俗共赏，偏清雅。** 用雅的方式诠释俗：保留俗的功能（吉庆标记时刻，热闹表达人情），去掉堆砌。雅不能脱离日常使用成为空中楼阁。
5. **不侵入。** 人们的生活越来越各自独立，产品不应把自己推到人面前。
6. **破执，但有尺度。** 执有三重，都要防：
   - **我执**：设计者想表达自己的趣味或身份，例如用符号表明“中式”、用讲究区别于大众。以“用为本”对治。
   - **法执**：执着于规则本身。本文的原则和各项目的指南是检验工具，不是戒律；理由站得住，可以不按规则。
   - **空执**：执着于否定，例如“不许用某种形式”、把简约当目标、无穷无尽地自我怀疑。

   阶段不能跳（见山是山，见山不是山，见山还是山）：平时照原则和指南做，这是第二阶段的功夫；“这里可以不按规则”的判断属于第三阶段，归负责人，不能写成规则。做法上有三个条件：只在具体的设计上原则与用处发生冲突时才提；问一轮，由负责人判断；判断后记下理由，情况不变就不再重提。
7. **温润是结果，不是手段。** 君子温润如玉。前面几条做到位，东西给人的感觉应当是温润的：不冷峻，不枯寂，不刻意。它不列为原则，也不靠材质或效果去做出来；它用来在最后回看：这件东西对人是否温和。

## 2. 七条原则

每条都带一个检验问题。审查设计时逐条问，答不上来的地方就是要改的地方。

| 原则 | 意思 | 检验 |
|---|---|---|
| 用为本 | 形式从用处来。每个元素都要说得出它帮用户做了什么。这条管“该不该有” | 去掉它，用处少了吗？ |
| 工巧 | 美感来自把必要的东西做精：比例、对齐、节奏、字的排法、动效的缓急。不来自添加。这条管“做得好不好” | 必要的东西，每一样都做到位了吗？ |
| 模件 | 少量构件加组合规则，生出所有界面。构件统一，组合可以变。新需求先用现有构件拼，拼不出再加构件 | 新需求能用现有构件拼出来吗？ |
| 体宜 | 布局和控件跟着内容、设备、任务变。统一的是含义和视觉语言，不是尺寸和版式。真正的下限不动（命中区、最小字号、文字对比） | 换个场合，同一个动作还是同一个意思吗？ |
| 计白当黑 | 空白是有功能的另一半：分组、引导视线、让内容成为主角。不为显得讲究而留白 | 这块空白在帮内容，还是在摆姿态？ |
| 素底点红 | 平时素净，只在值得的时刻有一点强调或庆祝。强调越少，每一次越有分量。“红”是比喻，不指红色；“素”指底子不抢，不指白或灰 | 这次强调配得上这个时刻吗？ |
| 分寸 | 三层：不打扰（不争夺注意力）、不越权（不替用户做他没要求的事；可以建议，由用户决定，做过的能撤回）、不邀功（不夸自己做了什么） | 用户没找它时，它安静吗？它做的事，是用户要的吗？ |

出处，供理解用，不是装饰的依据：

- 工巧：《考工记》“天有时，地有气，材有美，工有巧”。
- 模件：雷德侯《万物》指出的中国造物传统，汉字、斗拱、活字、瓷器都是标准构件的组合。
- 体宜：《园冶》“巧于因借，精在体宜”。
- 计白当黑：书法和篆刻的布局方法。
- 素底点红：水墨画上的一方朱印；平日素净、过年贴红的生活习惯。

## 3. 多与少：先问必要，再看数量

1. **判断标准是必要，不是多少。** 一个元素该不该在，由“用为本”的检验决定。信息可以密，只要每一项都必要且有秩序；装饰应当少。清雅指的是没有多余的东西，不是东西少。
2. **数量是提醒线，不是上限。** 只按必要来加，容易得到每一项都有用、合起来却庞杂的结果。下面的数字用来在这时提醒人停下来重新组织。

| 情形 | 参考数量 | 依据 |
|---|---|---|
| 整个产品的结构 | 每层并列的入口 3–5 个；层数尽量不超过 3 层 | 不限制功能总数，限制每一层的宽度：三层可以容纳一百多个功能，而用户任何时刻只面对 3–5 个选择。每层宽度来自记忆与决策的限度；“不超过 3 层”是经验判断，没有研究依据 |
| 需要用户同时放在脑子里的东西（对比几个版本、跨页面记住刚才的数值） | 不超过 4 | 工作记忆同时保持约 3–5 个组块，视觉工作记忆约 3–4 个 |
| 一组并列可见的选项 | 约 5 个以内不必分组；更多就分组，每组 3–5 个，组数也尽量 3–5 | 可见的选项靠辨认而不是记忆，所以可以比 4 多；但决策时间随选项数增长，分组能抵消 |
| 一屏内的主操作 | 1 个 | 设计建议，来自平台惯例，不是研究结论 |

3. **超过提醒线时，先分层，不先删功能。** 默认只露出常用的，细节放到下一层；或者分组；或者拆成步骤。只有确认某项不必要时才删。
4. **前两层靠交互设计简化，细项只在最深一层摊开。** 成排的细项（例如十几个各自调节的滑杆）不放在前面。前面用一个简化的操作代替它们（例如一个整体强度）；用户确有需要、主动进到最深一层时，才把细项摊开各自调节。
5. **不要把“7±2”当作菜单长度的规则。** 那是 1956 年关于短时记忆的估计，后来的研究把数字修正为约 4，而且菜单靠辨认，本来就不受这条限制。

说明：研究给出的是记忆和决策的限度，没有给出“功能数量”的结论；上表的数字是从这些限度推出来的设计建议。选择过载的效应在综合研究中平均接近于零，只在选项复杂、任务难、用户偏好不明确时明显，所以表里没有给“选项总数”设硬上限。

## 4. 不做的事

1. **不为表明身份或显得丰富而加东西。** 传统纹样、书法字体、仿古材质不用来表示“中式”，用户用不到的元素不用来充实版面。但也不执着于“不用”：内容或用处确实需要时，任何形式都可以用（破执：不执着于表象，也不执着于不用某种形式）。
2. **君子之交：产品不主动找用户。** 界线看是谁发起的。用户发起或用户订阅的事可以告知，只告知一次；产品自己想让用户回来的事，不做。不用红点、弹窗、开屏、连续提醒争夺注意力，不诱导分享，不催促评价。产品是否商业化都不例外：订阅快到期关系到用户自己的利益，告知一次；新功能在用户打开产品时于相关位置安静出现，不推送；“你很久没来了”这类召回不做。
3. **重点的、便捷的放外面，深层的放里面。** 完成主要任务必经的功能不放到第二层；放到里面的，应当是用户确有需要才会主动进去找的。不为版面好看而藏起常用功能。
4. **庆祝只给用户花了心血的事，并且不拖泥带水。** 可以用可观察的信号判断（花的时间、步骤数、处理的数量）；拿不准时不庆祝。庆祝要短，不挡住下一步操作，不需要用户手动关掉。保存、切换、打开这类平常操作不庆祝；按钮回弹、操作成功的轻提示属于功能反馈，照常保留。

## 5. 在项目里怎么用

1. 项目的设计指南在开头引用本文。
2. 新界面审查时，先过第 2 节的七个检验问题，再过第 3 节的数量提醒线，最后才是项目指南里的数值检查。
3. 规则不必都从七条原则推出来，平台惯例、无障碍下限都是正当来源。关键是设计的理由站不站得住，这由负责人判断。

## 6. 未定

- **自己的视觉语言**：本文只定了方法，没有定具体的样子。2026-11-14 试过一轮（中文排版、墨色强调、宣纸材质、方圆的形、笔势动效），负责人的结论是：自己的风格不是一两天能设计出来的，实现上继续沿用苹果的方案（各项目指南里的 HIG 为主）。这一轮的试样留在 `design/prototype/aesthetic/compare.html` 和交互原型画布的“视觉语言探索”一排，都是讨论稿，不是规范。

- 本文目前放在 Dapple 仓库里。用到第二个项目时，再决定是否移到独立的位置。
