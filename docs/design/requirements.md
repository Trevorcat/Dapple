## 1. 设计原则

1. **自动是默认。** 照片到达即处理，缩略图显示处理后的结果；没有“增强”按钮。
2. **完整的手动控制。** 光线 / 颜色 / 曲线 / 效果 / 细节 / 分级 / 裁切达到 Lightroom 级别；自动结果只是起点。
3. **明暗：描述，不猜意图。** 用白话说出最接近的类别（明亮/均衡/深沉 × 柔和/自然/强烈），向它轻微增强；用户可从 3×3 实时预览中选任意目标。专业名（高长调…）只作为小号次要标注。
4. **照片是内容层。** 界面中性，强调色只给主操作和选中态；照片周围用中性灰。
5. **亮色优先，跟随系统。** 无应用内主题开关。每个自定义颜色同时有亮 / 暗两套。
6. **Apple HIG 为主，Android 用 Material 3。** 视觉克制与层级按 HIG；行为语义（48 dp 目标、inset、返回、前台服务）按 Android。
7. **状态诚实。** 到达中 / 处理中 / 预览 / 原片 / 失败逐张可见；失败必须给出可执行的下一步。
8. **一切可逆。** 多级撤销 / 重做；还原、粘贴、同步、改默认风格都有带“撤销”的提示条；不覆盖原片。
9. **选片与发布由人决定。** 不自动发帖；发布前提示异常项。
10. **文案克制。** 不写说明句、不教学、不居高临下、不用学术词。见指南第 11 节。
11. **按窗口尺寸适配，不按机型。** 功能不随尺寸类别变化。
12. **平台无关的发布。** 平台预设（比例/尺寸）+ 系统分享面板，相册兜底。
13. **手指相对操作，眼睛留在照片上。**（v0.5）编辑器里没有传统滑杆：手指落在哪里无关，值随位移变化；读数在手指之外；交互进行中不重排；触感只在地标。详见 4.15 与指南第 15 节。

## 2. 信息架构与导航

### 2.1 目的地

三个一级目的地：**照片 / 风格 / 设置**。一个全屏编辑页，若干全屏任务页（创作工具、发布、发布结果）。

```
引导（仅首次）
└─ 照片 ─┬─ 首页网格（今天 / 昨天）
         ├─ 多选模式 ─┬─ 合成方式 → 创作工具(HDR/全景) → 任务进度
         │            ├─ 存相册
         │            └─ 发布 → 系统分享 / 相册兜底 → 发布结果
         ├─ 看图/编辑 ─┬─ 更多菜单 ─┬─ 复制设置 / 粘贴设置
         │            │           ├─ 同步设置…
         │            │           └─ 还原为自动结果（确认）
         │            ├─ 分享 → 发布
         │            └─ 8 个调整分组
         └─ 昨天分组入口 → 创作工具(HDR/全景/视频转实况|动态照片)
   风格（默认风格库 + 导入）
   设置（相机 / 自动处理 / 发布）
```

### 2.2 导航随形态

| 形态 | 判定（建议，按窗口宽度，不按机型）【待验】 | 全局导航 | 编辑布局 |
|---|---|---|---|
| 手机，iOS | 宽 < 600 | 悬浮玻璃胶囊标签栏，258×62，底部 | 【已被 4.15 取代】全屏照片 + 浮窗（4.15.14） |
| 手机，Android | 宽 < 600 | M3 导航栏，高 104（含手势区） | 同上 |
| iPhone Duo 外屏 | 宽 < 600（466×678 pt，由 3x 换算【待验】） | 同手机 iOS | 同手机；面板大档 68% 屏高 |
| Android 折叠屏内屏 / 展开 | 宽 ≥ 840（N5 内屏 840×760 dp，**真机宽度未测**【待验】） | 左侧导航轨，宽 80 | 左照片 + 右常驻检查器（宽 336） |
| iPhone Duo 内屏横向（主形态） | 宽 ≥ 840（890×626 pt【待验】） | 悬浮胶囊标签栏 | 左照片（550）+ 右检查器（340） |
| iPhone Duo 内屏竖向 | 宽 600–839（626×890 pt） | 悬浮胶囊标签栏 | 上照片（626×387）+ 下检查器（626×400，标签） |

- 【已被 4.15 取代】本表“编辑布局”列（底部面板、右侧检查器、桌面姿态下半检查器）以 4.15.14 为准；全局导航列不变。
- 窗口类别在运行中会变（折叠、旋转、分屏）：选中照片、选择集、滑杆值、面板档位、展开的分组必须保持。
- 不锁方向。
- 【缺陷】原型用 `device` 参数切换布局，不是按宽度；实现必须用 `LayoutBuilder`/`MediaQuery.sizeOf`。
- 【缺陷】Large 不含：引导、多选、合成方式、HDR/全景/视频转动态、发布页、发布结果、风格库的导入。大屏必须具备与手机相同的全部功能（见 4.14）。

### 2.3 返回顺序（Android 预测性返回）

退出对话框/菜单 → 退出多选 → 退出数字输入 → 关闭最近打开的浮窗（收起的药丸也算）→ 退出沉浸（隐藏的顶栏 / 坞）→ 退出编辑 → 回到网格。（v0.5：原“退出聚焦”由沉浸取代，见 4.15.6 表第 24 行。）

### 2.4 导航显示规则

| 页面 | 标签栏/导航栏 |
|---|---|
| 首页（非多选）、风格、设置 | 显示 |
| 首页多选 | 被选择栏替换 |
| 编辑、创作工具、发布、发布结果 | 隐藏 |

切换标签时清除选择集并解除网格冻结。

## 3. 全局规则

### 3.1 逐张状态

| 状态 | 网格表现（手机） | 可点开 | 可选中 | 说明 |
|---|---|---|---|---|
| 到达中 | 占位底色，居中“接收中 N%”+ 3 高进度条；图像不显示 | 否，提示“正在接收” | 否 | 到达中的照片不进入编辑导航列表 |
| 处理中（预览） | 显示相机内嵌预览，不套用处理；右下 22 圆形遮罩 + 转圈；左下空心圆点 | 是（编辑器信息行加“· 预览”，Large） | 是 | 发布时提示“第 N 张还在处理，现在发出的是预览图” |
| 已处理 | 无标记 | 是 | 是 | 不再给每张挂“RAW” |
| 已调整 | 左下蓝点 `#4C8DFF`，白描边 1.5 | 是 | 是 | 任一参数 ≠ 默认，或 风格/明暗/调色盘有覆盖 |
| 建议检查 | 左下琥珀点 `#F0A020` | 是 | 是 | 由引擎给出标志（如暗部噪点高）【开放：判据】；发布页提示“第 N 张暗部噪点较多” |
| 传输中断 | 琥珀色 3 描边 + 18% 琥珀罩 + 左上“传输中断”标签 + 居中“重试”（64×44） | 否，提示“传输中断，点「重试」” | 否 | 点“重试”后恢复为正常流程，提示“已重新传输” |

- 色点同时有形状差异（空心 / 实心）；颜色不是唯一信息，aria 标签带文字（“已调整”“建议检查”“处理中，当前为预览”）。
- 【缺陷】Large 的处理中用确定性圆环、“已调整”点为白色；Main 用转圈、蓝点。统一为 Main，圆环可在引擎提供真实进度时采用。
- 【开放】RAW 迟到子状态：研究 Q6/Q8 要求“预览 / 原片已到”分开显示。原型只有“预览”一个态。引擎需上报“原片已到”。
- 状态转换：到达中 → 处理中 → 已处理，换图时不得引起布局跳动。

### 3.2 撤销 / 重做

- 编辑器顶栏常驻撤销、重做；无历史时 `aria-disabled`，不透明度 0.4。
- 记录对象（Main）：每张的 风格、风格强度、调色盘、明暗目标、明暗强度、全部滑杆，以及全局默认风格、默认明暗强度。
- 连续拖动同一控件 800 ms 内合并为一步（Large 为 700 ms）；栈深 80（Large 60）。v0.5：**一次连续手势（含精细带变化）无论多长 = 一步**；窗口内数值输入 = 一步；分类复位 = 一步（4.15.10）。
- 【缺陷】Main 的历史栈是全局的，跨照片共享：在 A 照片上点撤销可能撤回 B 照片的改动。规定改为**每张照片独立栈**，全局默认值改动单独记录。【开放：全局动作是否进入栈】
- 带撤销的提示条动作：还原为自动结果、粘贴设置、同步设置、新照片默认风格、Large 的“用于此照片 / 设为默认”。撤销提示 8 秒；普通提示 2.4 秒。
- 不重定义系统撤销手势（摇一摇、三指滑）。

### 3.3 提示条

- 单实例，新的替换旧的；常驻 `aria-live=polite` 区域。
- 位置按屏幕计算，永远不压住主按钮（见指南 9.7）。
- iOS：深色药丸，圆角 20；Android：Snackbar，圆角 4，全宽，最小高 48。动作按钮 ≥44 高。

提示条文案清单：

| 触发 | 文案 | 动作 |
|---|---|---|
| 点到达中的照片 | 正在接收 | — |
| 点传输中断的照片 | 传输中断，点「重试」 | — |
| 重试 / 重新连接 | 已重新传输 / 已连接 | — |
| 合成选择不足 | 至少选 2 张 | — |
| 存相册 | 已存入相册「Dapple」· N 张 | — |
| 复制设置 | 已复制设置 | — |
| 粘贴设置 | 已粘贴设置 | 撤销 |
| 同步设置 | 已同步 N 张 | 撤销 |
| 还原 | 已还原为自动结果 | 撤销 |
| 改默认风格 | 新照片默认使用「X」 | 撤销 |
| 转入后台 | 转入后台 | — |
| 后台任务完成 | {HDR 合成 / 全景 / 实况照片}已加入「昨天」 | — |
| 后台任务失败 | 没能对齐这几张 | 查看 |
| 打开目标 App | 已打开{App} | — |

### 3.4 对话框与面板

- 全部带 `aria-modal`，Esc 关闭，点遮罩关闭，焦点移入、关闭后归还。
- 破坏性确认用 `alertdialog`；其余 `dialog`；菜单 `role=menu`。
- 取消语义：任何“取消”恢复打开前状态（含选片弹窗）。

### 4.2 首页

#### 4.2.1 结构（自上而下）

1. **标题区。** iOS：大标题“照片”（34/41，700）+ 右侧胶囊按钮“选择”（高 36，最小宽 64，底色 chip）。Android：顶栏高 64，标题 22/28、字重 400，右侧“选择照片”图标按钮（48）。选择中标题为“选择照片”或“已选 N 张”。
2. **连接卡。** 圆角 16（Android 12）；10 圆点 + 标题 + 一行状态 + 可选动作按钮（高 36）；接收中显示 4 高进度条（`progressbar`）。
3. **后台任务条**（有后台任务时）。`role=status`，最小高 44：转圈 + “正在合成 HDR / 正在拼接全景 / 正在生成实况照片|动态照片” + 百分比。
4. **“新到 N 张”胶囊**（冻结时）。高 44，强调色底，居顶部浮层；点击滚回顶部并插入。
5. **今天分组。** 标题“今天 · 外滩”（17/600），右侧计数“N 张 · 14:20 起”；选择中右侧加“全选 / 取消全选”（44 高）。网格 3 列，间距 2，方块。
6. **昨天分组。** 标题“昨天 · 陆家嘴”，计数“N 项 · 19:05”；先是合成入口卡（3 行），再是 3 列网格。
7. **底部导航 / 选择栏。**

#### 4.2.2 连接卡状态

| 场景 | 圆点 | 标题 | 状态行 | 动作 |
|---|---|---|---|---|
| 正常接收 | 绿（okIcon） | Sony α7R V · 已连接 | 正在接收第 N 张 · 已处理 M 张 | — |
| 正常处理最后一张 | 绿 | 同上 | 正在处理最后 1 张 | — |
| 全部完成 | 绿 | 同上 | 本组 12 张已处理 | — |
| 传输中断 | 琥珀 `#F0A020` | 同上 | 1 张传输中断（警告色） | 重试 |
| 已断开 | 红 `#D64545` | Sony α7R V · 已断开 | 最后收到第 N 张 | 重新连接 |
| 未连接 / 相册为空 | 中性（track） | Sony α7R V · 未连接 | 没有新照片 | 连接 |

- 已断开：已到的照片保留，新照片停止；点“重新连接”后恢复，提示“已连接”。
- 相册为空：不显示分组；中部空状态——48 相机线性图标 + “还没有照片”（17/600）+ 主按钮“连接相机”（高 44，圆角 14 / Android 26）；“选择”入口隐藏。
- 传输失败的“重试”有两处：连接卡动作、逐张按钮；任一处恢复即清除两处状态。
- 【缺陷】原型相机名称固定“Sony α7R V”。多相机时的当前相机选择规则【开放】。

#### 4.2.3 网格规则

- 最新在前。**滚动超过 48 dp 或进入选择模式时冻结列表**，不重排；新到的数量累积到“新到 N 张”胶囊（裁决）。点击胶囊：滚回顶部、解除冻结。
- 点击 → 进入编辑（当前照片 = 点击项）；长按 450 ms → 进入多选并选中该张；多选中点击切换。
- 到达中 / 传输中断项不响应长按。
- 网格列数应按窗口宽度计算（手机 3 列；大屏见 4.14）。

#### 4.2.4 昨天分组与合成入口

入口卡 3 行（缩略图堆叠 + 标题 + 副标题 + ›）：

| 标题 | 副标题 | 打开 |
|---|---|---|
| HDR · 3 张包围曝光 | −2 / 0 / +2 EV | HDR 工具，来源=自动识别 |
| 全景 · 4 张连续 | 水平拍摄 | 全景工具，来源=自动识别 |
| 视频 → 实况照片 / 动态照片 | 0:14 · 截取 3 秒 | 视频转实况/动态工具 |

- iOS 只出现“实况照片”，Android 只出现“动态照片”。
- 下方网格：未合成的包围曝光 3 张、全景 4 张、视频 1 张（角标为 EV / 序号 / 视频；视频有 36 圆形播放标），再加合成结果（角标为类型：HDR / 全景 / 实况照片|动态照片，强调色底），结果在最前。
- 合成结果与这些项可被选择、可打开编辑、可发布（裁决 P0-9）。
- 自动识别的判据（引擎侧）【待验】：同机身，时间戳间隔数秒内，曝光值不同 = 包围曝光；时间戳连续且有重叠 = 全景；Sony MakerNote Sequence 字段在 A7R V 上未验证。

#### 4.2.5 手机相机拍摄（测试便利，机主要求）

没有专用相机时，用手机自带相机直接拍摄并调色。仅 Android；不是产品主线，不扩展成相机 App。

- **入口。** 首页顶栏“选择”按钮左侧加相机图标按钮（label“拍照”，48）；大屏布局相同；选择模式下隐藏。
- **权限。** 点击时请求 CAMERA。拒绝：提示“没有相机权限”+“重试”；永久拒绝：同提示+“设置”（打开系统设置）。
- **拍摄页。** 原生全屏（CameraX，黑底）：取景框（4:3，完整显示）、快门、镜头切换、关闭，顶部小标“RAW + JPEG”或“JPEG”。无说明文字。一次快门即返回。
- **格式。** 镜头支持 ImageCapture RAW_JPEG 时同时输出 DNG + JPEG，否则只出 JPEG；取该镜头可提供的最高分辨率。
- **回退。** CameraX 打不开相机（或设备无相机）时改用系统相机（ACTION_IMAGE_CAPTURE，FileProvider URI），只得 JPEG。
- **入库。** 作为新照片进入图库，有 DNG 时 DNG 为源、JPEG 为即时预览与配对（同 RAW+JPEG 配对规则）；同时写入相册「Pictures/Dapple」（DNG、JPEG 各一份，同实况照片的约定，且该目录不会被相册扫描重复导入）；走与相机到达完全相同的自动处理管线；入库后立即打开编辑器。
- **手机 DNG 的已知局限。** LibRaw 读取 DNG 的颜色矩阵与方向；DNG 操作码（GainMap 镜头阴影、WarpRectilinear 畸变、FixVignetteRadial）LibRaw 不执行，所以手机 RAW 角部偏暗/偏色、广角有畸变，需要引擎自己实现这些操作码才能与手机直出一致【待验】。
- 隐私：照片只存在手机本地，不上传。

| 手势 | 在窗口内拖动 = 移动窗口（窗口宽 = 视频的 22%，起点 0…78%）；落在封面线附近（±4%）拖动 = 移动封面（限窗口内）；键盘 ←/→ 2% 步进，Shift + ←/→ 移动封面 |

| 开关 | 防抖（默认开）、静音（默认开） |
| 主按钮 | 生成实况照片 / 生成动态照片 |

- 窗口宽度 22% × 14 s = 3.08 s，与“3.0 秒”文案不一致【缺陷】；规定窗口长度为固定 3.0 s（按视频时长换算宽度），视频时长不得写死“0:14”。

- 平台术语：iOS 只说“实况照片”，Android 只说“动态照片”。
- 【待验】Android 动态照片（Motion Photo）在 ColorOS 相册、微信、小红书、微博中的识别与保留；iOS 保存 Live Photo 的 PhotoKit 兼容性。
- **色深与色彩（负责人决定 2026-11-12）**：
  - 母版保持素材原有色深，不做 10→8 bit 截断：视频部分为 HEVC Main10（4:2:0），静帧对 HDR 素材用 Ultra HDR JPEG。
  - 源色彩自动识别，识别不了时可手动选：自动 / 标准 / S-Log3 / HLG。
  - 8-bit 兼容版只用于分享到不支持 10-bit 的目的地。
  - 解码：硬件优先，不支持时（如 Sony H.264 4:2:2 10-bit）用 FFmpeg（LGPL）软解。
  - 音频：PCM 转 AAC 后保留，静音开关照旧。

#### 4.9.5a 动态照片跟随编辑（含胶片模拟）（负责人决定 2026-11-12，排期见引擎路线图）

胶片模拟定位为通用后处理：照片与视频共用同一条渲染管线与同一套参数。

- **编辑方式**：动态照片 / 实况照片在编辑器中像普通照片一样编辑。对静帧的整套编辑（包括胶片模拟）同样作用于视频部分的每一帧，用户不需要分别调整。
- **输入还原**：视频帧先按源色彩还原到场景线性光，再进入管线，与 RAW 走同一套节点。
  - S-Log3 / S-Gamut3.Cine：按 Sony 公开公式反算，效果最佳。
  - HLG：按公式反算。
  - 普通 Rec.709：近似反算，高光已被相机压缩，效果有限，界面不额外说明。
- **时间一致性（不得闪烁）**：
  - 依赖画面内容的参数在静帧（封面帧）上计算一次，再锁定给整段视频：自动明暗与调性、去朦胧的大气光、自动白平衡等。
  - 颗粒每帧不同（随机种子包含帧序号）。同一帧重复渲染时结果逐位一致。
- **输出**：
  - 应用了胶片模拟时输出 SDR（胶片 = 印放 + 扫描，观感本身是 SDR）。
  - 未应用胶片时，保持 4.9.5 的 10-bit / HDR 母版规则。
  - 静帧与视频封面帧的渲染结果须一致（同一节点图、同一参数；色差预算见引擎文档）。
- **性能目标**：3 s × 30 fps @1080p。GPU 执行器整段 ≤ 3 s（N5，估计值，待真机验证）；CPU 兜底须能完成，并显示进度、可取消、可后台。
- **前置条件**：渲染管线迁移阶段 (b) 完成，胶片模拟已成为 GPU 节点，见 `docs/engine/pipeline-architecture.md` §15。
- **实现状态（2026-11-12，第 8 波，详见 `docs/engine/pipeline-architecture.md` §30）**：
  - 已完成（桌面软件路径，已测）：`VideoFrameSession`（`core/engine/video`）把解码帧（半精度线性 RGB，无 10→8 bit 截断）送进与静帧相同的节点图；胶片曝光匹配、调性分析、查找表、去朦胧求解都取自参考帧并锁定；颗粒与乳剂微结构随帧序号变化（同帧重复渲染逐位一致），印放眩光噪声固定；输出 10-bit（P010）或 8-bit（I420）；`dapple motion render` 命令端到端（解码、编辑含胶片、编码）。
  - 已测数字：与静帧管线逐像素一致（最大差 0）；10-bit 渲染后仍有 641 / 652 个亮度码值（8-bit 路径 219）；静态片段关颗粒后帧间差为 0；1080p CPU 每帧 21-47 ms（含胶片）。
  - Android 导出路径已接入（`EditSpec` / `SoftwareMedia.clip(edit)` / `LiveBridge.trim(edit)` / Dart `EditedClip`），不带 `edit` 时行为与以前完全相同；编辑器尚未传 `edit`（`app_state.dart` 的接入点已留好）。
  - 未完成 / 未验证：真机 HEVC Main10 硬件解码 → 节点图 → 硬件编码、耗时与发热（清单见 §30.5）；GPU 执行器的 10-bit 输出（目前 GPU 只输出 8-bit，10-bit 走 CPU 执行器）；硬件解码缓冲零拷贝进入节点图。

#### 4.9.6 任务进度与失败

任务从主按钮开始，弹出 `alertdialog`（遮罩 scrim，内边距 24，圆角 iOS 20 / Android 28）：

| 状态 | 标题 | 内容 | 按钮 |
|---|---|---|---|
| 进行中 | 正在合成 HDR / 正在拼接全景 / 正在生成实况照片\|动态照片 | 步骤文字“对齐 → 合并 → 处理”（按进度 0–33 / 34–67 / 68–100 分段显示当前步）；6 高进度条（`progressbar`，0–100） | 转入后台（chip）、取消（强调色文本） |
| 失败 | 没能对齐这几张 | 无正文 | 换基准帧（主按钮）、取消 |

- 取消：立即终止任务，回到工具页，选择与参数不变。
- 转入后台：回到首页，首页顶部出现后台任务条（含百分比）；完成时不强行跳页，只提示“{名称}已加入「昨天」”；后台失败时提示“没能对齐这几张”+“查看”，点“查看”回到工具页。
- 完成（前台）：回到首页，结果出现在“昨天”最前，同样的提示。
- 失败时“换基准帧”：切换为下一张已选照片为基准，关闭弹窗回到工具页（**不自动重试**）。
- 视频转实况无失败态原型。【开放】
- 【缺陷】原型进度是定时器模拟（每 260 ms +9%）。真实任务由引擎回调：阶段（对齐 / 合并 / 处理）+ 百分比，可取消，可后台。

**十一条决策（负责人批准，不得改动）**

1. 编辑器内**任何地方都不出现传统滑杆外观**；以手指的**相对操作**取代。（设置页、创作工具的滑杆不在此列。）
2. 照片铺满屏幕（避让系统 inset）。悬浮极简顶栏：返回、撤销、重做、存相册。底部悬浮**分类坞**。

4. 窗口打开时（调整模式）：窗外单指横拖 = 相对映射改值（速度相关增益 + 精细带）；窗外单指竖拖 = 切换分类内参数；长按静止 = 看原片；双指 = 缩放 / 平移；双击 = 适合 ↔ 2×。读数显示在照片上缘；拖动时窗口收成一行。仅在地标处给触感。复位：双击行、窗头复位图标、可见的白色“自动”标记。无障碍：每个参数都是可调整语义节点，可点数值输入。

#### 4.15.4 浮窗

**结构（紧凑卡片）。**

| 区 | 规格 |
|---|---|

| 手势 | 动作 |
|---|---|
| 轻点参数行 | 设为活动参数 |
| 双击参数行 | 该参数复位到自动位（4.15.10） |

**收起（药丸）。** 高 40，宽 120–220：分类图标 + 活动参数名 + 数值 + ✕（关闭窗口，44 命中）；轻点药丸本体展开。药丸仍保持**调整模式**（窗外单指继续调整活动参数）。

**拖动中。** 窗外调整手势开始的瞬间，窗口缩成一行读数（名称 + 数值，不透明度 0.7，缩放到药丸尺寸，原位不动）；手指抬起 150 ms 后以弹簧恢复展开（4.15.13）。**拖动期间窗口的大小、位置不因其他原因改变。**

**位置与吸附。**

- 默认：停靠**惯用手一侧**边缘（4.15.12），贴底部分类坞之上 12。第二个窗（仅宽度 ≥ 600 dp）默认停靠另一侧。
- 可拖动；松手时按“位置 + 速度投影”（`decelerationRate 0.99`，投影 = 位置 + 速度 × 0.099 s）选最近的边：**左 / 右 / 下**（不吸顶）。吸附到左右边：纵向自由、被限制在 [顶栏区底, 坞顶 − 窗高]；吸附到下边：窗横向自由，窗变为“宽卡片”（宽 ≤ 480，参数分两列，列优先排序）。
- 与系统手势区的避让：左右吸附位的边距 = max(12, 该侧 `systemGestureInsets`)；不得压住底部强制手势区（4.15.15）。
- 用户拖过的窗口为“已固定”：惯用手自动切换（4.15.12）不再移动它；在设置里手动改惯用手时清除固定。
- 位置按（宽度类别 × 方向 / 姿态）分别记忆，窗口类别改变（折叠、旋转）时用该类别的记忆；没有记忆用默认。

**窗口数规则。**

| 窗口宽度 | 同时展开 |
|---|---|
| < 600 dp | 1 个：点另一个分类 = 在原位置**替换内容**（弹簧交叉淡入，180 ms） |
| ≥ 600 dp 且高度 ≥ 480 dp | 最多 2 个：点第三个分类时替换“最久未操作”的那个；两窗里只有一个“获焦”（头部高亮、其活动参数是手势的目标）；轻点另一窗的任一行或头部 = 切换获焦 |

**直方图窗（仅宽度 ≥ 600 dp）。** 常驻，不计入两窗上限，不能关闭、不放进任何可折叠容器（负责人规则，取代 4.6.1 / 4.14.1 中“固定在检查器顶部”）。默认 168×88（含 11 条区域条的简化版，保留 p5/p50/p95 虚线），默认在**非惯用手一侧的上角**（顶栏之下）；可拖动、吸附 4 个角 / 边，可缩到 120×64，不可收成药丸；拖动调整时**不随窗口缩成读数**（不透明度保持 0.85），因为调光线时正需要看它。对比（长按）时同步显示原片直方图。紧凑宽度（< 600 dp）：没有常驻窗，直方图以迷你版（96×32）出现在 光线 / 曲线 / 风格 浮窗的头部下方，并在拖动这三个分类的参数时并入读数（4.15.9）。

#### 4.15.6 模式与手势语法

**浏览模式（无浮窗）**

- 单指横向快滑（轴锁，见下）：**仅在适合缩放时**切换上一张 / 下一张（页面跟手，松手按速度投影：位移 > 35 % 宽度或速度 > 600 dp/s 则翻页，弹簧收敛）。
- 放大后单指拖动 = 平移（这不是调整）；单指竖拖在适合缩放时无动作。
- 双指 = 缩放 / 平移；双击 = 适合 ↔ 2×；长按 = 原片；轻点空白 = 沉浸开关。

**调整模式（至少一个浮窗展开或收起）**

- 单指拖动**全部用于调整**（含照片上）；放大后的平移必须双指。
- 窗外单指拖动，按活动参数的类型：1D → 轴锁后横拖改值 / 竖拖切参数；离散 → 轴锁后横拖步进 / 竖拖切参数；2D → 不轴锁，二维相对移动（4.15.8）；动作行不会成为活动参数。
- 轻点照片空白（决策）：**展开的窗口收起为药丸；全部已是药丸时再点则展开**；永不退出调整模式。退出调整模式 = 关闭最后一个窗口（药丸 ✕ / 再点坞里同一项）。

**轴锁（决定横向意图 / 竖向意图）**

1. 手指落下后，位移 < 10 dp：不锁，不改任何值。
2. 位移首次 ≥ 10 dp：与水平线夹角 θ < 35° → **锁横向**；θ > 55° → **锁竖向**；35°–55° 之间：继续观察到位移 ≥ 16 dp，按位移的较大分量决定。
3. 一旦锁定，**整次手势保持**。锁横向：竖向偏移不切参数，只用于精细带（4.15.7）；锁竖向：横向位移被忽略，只切参数。
4. 参考点 = 锁定瞬间的手指位置（精细带的竖向偏移、横向位移累积都从这里起算；前 10 dp 不计入改值，以保证起手抖动不改值）。
5. 10 dp 与 Apple 建议的约 10 pt 滑动滞后一致；θ 区间的数值【待验】。

**时间阈值**：长按 = 手指静止（位移 < 10 dp）满 380 ms；双击 = 间隔 ≤ 280 ms 且两点相距 ≤ 40 dp；因此单击动作在 280 ms 后才执行（若出现第二次点击则取消）。

| 22 | 轻点（照片） | 数字输入中 | — | 提交并退出输入（4.15.10） |
| 23 | 起点在顶栏 / 坞 / 直方图窗 | 任意 | — | 归该控件（顶栏按钮、坞横滑、窗口拖动） |
| 24 | 系统返回 | 任意 | 顺序 | 数字输入 → 关闭最近打开的浮窗（药丸也算）→ 退出沉浸 → 回到网格 |

实现约束（Flutter）：单指 / 双指判定、轴锁、长按、双击在一个自定义原始指针识别器中统一仲裁（不用互相竞争的 `GestureDetector`）；决定在落下后第一个 16 ms 帧内给出，不等待双击超时去做**调整**（只有“轻点空白”动作被双击超时延迟）。

#### 4.15.7 相对映射、增益与精细带（1D）

**核心公式。** 手指横向位移 Δx（dp，从上一帧的采样到本帧，参考点见 4.15.6）：

`Δ值 = Δx × g(v) × b × (范围 / 320)`

- 范围 = 最大值 − 最小值（如 −100…100 为 200；锐化 0…150 为 150）。**320 dp 的手指行程 = 全范围，增益 1、标准带时。**
- 手指**落在哪里无关**；方向：向右 = 增大（与 6.3 的符号一致：色温向右更暖，色偏向右更洋红，暗角向右变亮）。
- 值按每帧累加后再量化到参数步长（4.5 / 6.3 的步）；内部保留浮点，量化只发生在传给引擎时，避免慢拖时的“卡阶”。
- **跟手**：值不做任何平滑 / 延迟；动画只加在读数之外的界面元素上。

**速度相关增益 g(v)**（v = 近 60 ms 内沿活动轴的手指速度，dp/s，取绝对值）：

`g(v) = 0.35 + (2.5 − 0.35) × smoothstep((v − 40) / (900 − 40))`，v ≤ 40 → 0.35，v ≥ 900 → 2.5。

| 手指速度 | 增益 | 曝光（范围 200）每 dp | 100 dp 行程改变 |
|---|---|---|---|
| ≤ 40 dp/s（慢） | 0.35 | 0.22 单位 | 约 22 单位（1.1 EV） |
| 约 470 dp/s | 约 1.4 | 0.87 单位 | 约 87 单位 |
| ≥ 900 dp/s（快） | 2.5 | 1.56 单位 | 约 156 单位 |

数值为起点【待验：在 N5 真机上调，目标：单次拇指横扫（约 250 dp）能走完 ≥ 70 % 范围；慢拖 1 单位约 5 dp】。每帧只取沿锁定轴的速度；增益变化用 80 ms 内的线性插值过渡，避免跳变。

**精细带（竖向偏移 → 增益倍数 b）。** 锁横向后，手指相对参考点的竖向偏移 |dy|：

| 带 | |dy|（标准屏高，随可用高度缩放） | b | 读数标签 |
|---|---|---|---|
| 标准 | < 64 dp | 1 | 无 |
| 精细 | 64–160 dp | 1/4 | “精细 ×¼” |
| 极细 | > 160 dp | 1/16 | “极细 ×1/16” |

- 屏高缩放：阈值 × s，s = clamp(可用高 / 800, 0.6, 1)（横屏手机因此阈值变小）。
- 带边界滞后 ±12 dp，防止在边界上抖；带变化时 b 用 80 ms 过渡。向上或向下偏移均可（取绝对值）。
- 竖向偏移**只改增益，不改值、不切参数**——这是它与“竖拖切换参数”共存的方式：二者由**轴锁在起手决定**，整次手势互斥。想切参数必须新起一次竖向手势。
- 读数的刻度尺随带“放大”（4.15.9），让用户看见档位；不另加屏幕文字标尺。
- 起手就偏斜（35°–55°）时仍可能被判为竖向而切换参数：这是已接受的取舍；撤销无关（切参数不进撤销栈）。

**磁性吸附（自动位）。**

- 捕获窗口（值域占比）：标准带 ±1.5 %；精细带 ±0.5 %；极细带关闭。
- 进入捕获窗口时值吸到自动位并保持；保持期间累计手指行程，超过 10 dp（标准）/ 5 dp（精细）后挣脱，**从自动位起继续，不跳变**；手势起点已在自动位时，须先离开捕获窗口再触发。
- 触发一次触感（4.15.9）；挣脱后在离开捕获窗口 2 倍之前不再次捕获（防止连续震动）。
- 双向参数的 0（若 ≠ 自动位）只有视觉刻度，没有吸附。

**范围两端。** 值到达端点即夹住（无过冲），读数刻度尺的端点给 4 dp 橡皮筋回弹；第一次到达给“端点”触感一次；离开端点 ≥ 5 % 范围后才重新武装。

**离散控件。** 每 48 dp 手指行程步进一项（滞后 25 %，即回退需 12 dp 才反向步进），到头不循环；每步一次轻触感（档位地标）。

**参数切换（竖拖）。** 每 40 dp 一档（滞后 25 %），向下 = 列表下一行（窗内高亮同向移动）；到首 / 末行停住，给一次“端点”触感；不循环。窗内列表同步滚动以保持高亮可见。

#### 4.15.8 二维控件

通用：活动参数是 2D 时，**整个屏幕成为操作面**：不轴锁，单指在窗外任何位置相对拖动；位移（Δx, Δy）按下表换算；窗口与读数的行为同 4.15.9；操作面生效时照片外缘给一圈 2 dp 白色 40 % 描边作为状态提示（不占布局），并在读数区显示放大的迷你位置图（窗口此时缩成一行）。**两种离开 2D 参数的办法：轻点窗内其他行；无障碍操作。**【待验：只能点窗换行是否打断“眼不离图”的节奏；候选方案是“明显偏竖向的高速（> 900 dp/s）甩动 = 切参数”，有误触风险，暂不采用】

#### 4.15.9 读数、窗口缩略与触感

**读数。**

- 位置：照片上缘，水平居中，顶 = 顶栏底 + 8；绝不在手指下：手势开始时若触点距读数矩形 < 72 dp，读数改放到屏幕下部（坞之上）；手势中途手指进入读数区则读数不动、不透明度降到 0.4（**交互中不改布局**）。
- 内容：名称 + 数值（13/600 + 17/700 等宽数字，数值按 4.5 的显示格式，如“曝光 +0.35 EV”）；精细带时附标签“精细 ×¼”；下方一行**读数刻度尺**（只读，不可触摸，无滑块）：中心固定指针（强调色 2×18），刻度随值滚动；可见跨度 = 值域的 40 % × b（精细 / 极细时刻度放大，即跨度缩小，下限 5 个步长）。
- **自动位标记**：白色 2×14 刻度 + 上方小字“自动”，随刻度滚动；超出可见跨度时在刻度尺端点显示“‹ 自动”/“自动 ›”箭头。吸附成功时标记闪亮一次（不透明度 1.0 → 0.6，150 ms）。
- 2D 控件：读数区放大成迷你位置图 + 名称（无轴标签）。
- 紧凑宽度拖动 光线 / 曲线 / 风格 的参数时，读数右侧并入迷你直方图（96×32）。
- 形态：实底半透明黑 `rgba(0,0,0,.62)`，圆角 14，白字（指南 1 第 4 条：照片上的叠加物用实底半透明黑）；不接收触摸。
- 时机：手势开始 0 ms 内出现（淡入 150 ms）；松手后停留 600 ms，淡出 200 ms；复位 / 数字输入提交 / 参数被无障碍调节时同样显示。
- 对比（长按）时：读数位置显示胶囊“原片”（沿用 4.4.4）。

**窗口缩略。** 见 4.15.4。药丸里的数值与读数同步；药丸不含刻度尺。

**触感（仅地标；其余静音）。**

| 事件 | Android | iOS（后续） | 说明 |
|---|---|---|---|
| 吸附到自动位 / 复位完成 | API 34+：`SEGMENT_TICK`；API 30–33、更低：`CLOCK_TICK` | `UIImpactFeedbackGenerator(.light)`，intensity 0.7 | 地标（窄） |
| 离散项换档 / 竖拖切换参数 / 九格换格 | API 34+：`SEGMENT_FREQUENT_TICK`；其下：`CLOCK_TICK` | `UISelectionFeedbackGenerator.selectionChanged()` | 档位，轻 |
| 到达范围端点 | API 30+：`CONFIRM`；更低：`LONG_PRESS` | `UIImpactFeedbackGenerator(.rigid)` | 最强的一档；每次靠近端点只触发一次 |
| 九格“最接近类别”换入、调色盘默认点 | 同“自动位” | 同 | 2D 自动位 |
| 其余（连续改值、缩放、长按、读数） | 无 | 无 | 保持静音 |

- 经 `View.performHapticFeedback` 由平台通道发出（Flutter `HapticFeedback` 不含这些常量）；遵守系统“触摸反馈”开关；应用内设置里另有“触感反馈”开关（4.13，默认开）。两次触感间隔 ≥ 40 ms，同帧只取最强的一个。
- iOS：手势开始时 `prepare()`，手势结束释放。
- 触感可被用户关闭，因此每个地标都必须有视觉对应（自动位标记闪亮、迷你图高亮、端点读数顶住）。
- 【待验】Find N5 的马达表现；`SEGMENT_*` 在 ColorOS 上的实际强度；触感总量是否过多。

#### 4.15.10 复位、数字输入、撤销粒度

- **复位一个参数**：双击窗内参数行 → 该参数回到自动位（等价于删除该键的覆盖）；读数显示 600 ms；触发一次“自动位”触感；记一步撤销。
- **复位一个分类**：窗头 ↺ → 该分类全部参数回到自动位（“风格”分类 = 清除风格 / 风格强度 / 调色盘 / 明暗目标 / 明暗强度的覆盖；“裁切”含 `rot` `flip` `crop` `straighten`）；一步撤销；提示条“已复位{分类}”+“撤销”（8 秒，沿用 3.3）。分类无改动时 ↺ 隐藏。
- **自动位标记**：见 4.15.9，读数刻度尺上常显；窗内行以 ○ 表示“当前值 = 自动位”。
- **数字输入**：轻点窗内数值 → 该行数值变为输入框（系统数字键盘，带 −；显示单位 / 格式同 4.5，如 EV 输入“0.35”→ 取整到最近的步）；窗口上移避开键盘（这是离散操作，不属于“交互中不改布局”）；提交 = 回车 / 轻点照片；超出范围夹到范围并提示“已调整到范围内”；空输入 = 取消。一步撤销。
- **撤销粒度**：一次连续手势（含期间的精细带变化）= 一步；沿用 3.2 的 800 ms 合并（同参数连续手势）；切换参数、读数淡出不记录。每张照片独立栈（沿用 3.2 的规定）。

#### 4.15.11 无障碍

- **每个参数行 = 可调整语义节点**（Flutter `Semantics` + `increasedValue` / `decreasedValue` + `onIncrease` / `onDecrease`；TalkBack“增大 / 减小”，音量键）。每步 = 参数的一个步长（4.5 / 6.3；曝光 0.05 EV）；自定义动作：“大步增大 / 大步减小”（= 值域的 5 %）、“复位到自动”、“输入数值”。语义值 = 显示文本（如“曝光，+0.35 EV”），自动位处附加“，自动”。
- 2D：调色盘暴露两个可调整子节点（“冷暖”“浓淡”，文字只在语义里，沿用 4.7 的 aria 文本）；九格 = 9 个单选项（沿用 4.6.2）；曲线每个点 = 一个可调整节点；分级色轮 = “色相”“饱和度”两个可调整节点。
- **手势等价**：长按看原片 → 照片节点的自定义动作“显示原片 / 恢复成片”（决策 4 规定界面上不放对比按钮，所以只提供语义动作；大屏键盘：按住 Enter / 空格）；拖动改值 / 切参数 → 可调整节点 / 窗内点按；双击缩放 → 自定义动作“放大 / 适合”；窗口拖动 → 自定义动作“移到左 / 右 / 下”。
- 屏幕阅读器的“触摸探索”开启时，单指拖动用于探索而不是改值；窗外的相对手势不可用，改走可调整节点（不丢功能）。
- 值变化朗读：连续拖动时不播报；松手播报最终值；复位播报“已复位”。
- 动态字体：4.15.4 已规定窗宽 / 行高随字号变化；最大字号时行文字省略号，数值优先。
- “减少动态效果”：弹簧换成 150 ms 线性淡入淡出，无位移回弹、无缩放（4.15.13）。
- 色盲 / 触感关闭：每个地标有视觉对应（4.15.9）。

#### 4.15.12 惯用手

**设置**（4.13 增加）：设置 → 编辑 → **惯用手：自动 / 左手 / 右手**。左手 / 右手是手动值，立即生效（窗口不固定者以 350 ms 弹簧移到对应一侧，并清除“已固定”）。

**默认值**：自动；冷启动、数据不足时 = **右手**（拇指观察中右手约占多数【待验：Hoober 数据为美国样本】）。**自动的准确度必须在真机上测量；若不达标，自动不作为默认，默认改为“右手”，自动降为可选项（本规格的接口不变）。**【待验，验收线建议：≥ 20 名受试者、单拇指编辑 30 次手势内判对率 ≥ 85 %】

**自动推断（被动，无提示、无校准页）。**

特征（只对“单指、起点在窗外、位移 ≥ 60 dp 的滑动”和“单指轻点”取样）：

| 特征 | 来源 | 投票（+ = 右手，− = 左手） |
|---|---|---|
| 滑动弧线曲率 | 轨迹相对弦的最大偏移（sagitta）及其符号，结合滑动方向 | 右拇指向左划与向右划的弧向相反，系统性偏向可分；权重 0.5 |
| 触点椭圆朝向 / 大小 | Android `MotionEvent.getOrientation()`、`getTouchMajor/Minor`（Flutter `PointerEvent.orientation / radiusMajor / radiusMinor`，设备不报告则跳过） | 触点椭圆长轴的倾斜方向；权重 0.3（仅当设备上报且方差足够时启用） |
| 落点 x 分布 | 近 N 次单指落点的 x 均值 / 屏宽（偏向一侧） | 偏向右半 = 右手；权重 0.2 |

规则：

1. 每次合格手势产生分数 s ∈ [−1, +1]（加权和）与置信度 c；窗口 = 最近 40 次合格手势，c 加权平均得 S。
2. **多数票 + 滞后**：当前侧为右手时，S ≤ −0.35 且合格手势 ≥ 12 才切换到左手；反向对称。切换后 5 分钟内不再切换。
3. 置信度低（|S| < 0.35 或合格样本不足、或最近 2 秒内左右两侧交替落点 = 判为双手）→ **保持上一次的侧**。
4. **仅在手指抬起后切换**：任何指针按下、窗口拖动、长按、缩放、数字输入、弹簧动画进行中，一律不评估也不执行；空闲 ≥ 800 ms 后才执行，用 350 ms 弹簧把未固定的窗口移到新侧。**永远不在交互中重排**（HarmonyOS 智感握姿规则：不移动正在按住的目标，不打断进行中的操作）。
5. 记忆：当前侧、窗口缓存跨会话保存；设置里“重置自动判断”清除样本。
6. 不收集或上传触摸数据；样本只在设备上以聚合统计保存。

**惯用手影响什么**：默认窗口一侧（4.15.4）、第二窗在另一侧、直方图窗在另一侧的上角、手机横屏侧边竖轨的一侧（4.15.14）、读数不受影响（居中）。顶栏与分类坞不镜像。

#### 4.15.13 动效

原则：**跟手 → 离手继承速度 → 弹簧收敛**（HarmonyOS 引力动效三段；Apple WWDC18“流体界面”：没有突变、保留手指速度、软边界橡皮筋减速）。弹簧用 `mass = 1` 的物理参数（刚度 k，阻尼 c；阻尼比 ζ = c / (2√k)；约 95 % 到位时间 ≈ 3 / (ζ·ωₙ)）：

| 范围（时长档） | 用于 | k / c | ζ | 约 95 % 到位 |
|---|---|---|---|---|
| 小（150 ms） | 读数淡入淡出、高亮条移动、自动位标记闪亮、药丸 ⇄ 一行读数 | 1100 / 40（位移）；1100 / 66（透明度，临界阻尼，无过冲） | 0.60 / 1.0 | ≈ 150 ms |
| 中（200 ms） | 窗口展开 / 收起、窗内内容替换、窗口松手吸附（位移 ≤ 200 dp）、药丸展开 | 600 / 30；透明度 600 / 49 | 0.61 / 1.0 | ≈ 200 ms |
| 大（350 ms） | 惯用手换边、窗口长距离吸附（> 200 dp）、翻页收敛、姿态 / 窗口类别切换、照片避让位移 | 200 / 17（HarmonyOS 组件移动示例：刚度 200、阻尼 17）；透明度 200 / 28 | 0.60 / 1.0 | ≈ 350 ms |

- 窗口离手：以**离手速度**为弹簧初速度（`UIScrollView` 式投影：落点 = 位置 + 速度 × 0.099 s，取最近吸附边）；吸附位移按距离选档（≤ 200 dp 用中档，> 200 dp 用大档）。
- 跟手阶段 1:1，无动画（窗口跟指、翻页跟指）；超出边界（翻页首末张、窗口被拖出可用区）用橡皮筋 `(1 − 1 / (x·0.55 / d + 1)) · d`。
- **可打断**：任何动画被新输入打断时，保持当前位置与速度，以新目标重启弹簧（不重置、不跳变）；手指再次按下立即接管。
- 长按、手势识别等待不加动画；读数淡入由小档承担。
- 位移型动画在“减少动态效果”下换成 150 ms 透明度渐变（指南第 9 节规则）。
- 数值上的弹簧参数是起点【待验：在 Find N5 120 Hz 上看是否过软 / 过硬】。HarmonyOS 的 `responsiveSpringMotion`（response 0.15 s，dampingFraction 0.86）数值留作“跟手但略滞后”的备选（例如药丸跟随手指）。

#### 4.15.15 系统手势、安全区与铰链

- **一律在运行时读取，不写死**：`MediaQuery.viewPadding / padding`（状态栏、导航栏）、`MediaQuery.systemGestureInsets`（Android 返回手势区；Flutter 的 `MediaQueryData.systemGestureInsets`）、底部强制手势区（Android 的 `WindowInsets.mandatorySystemGestures`，需要时经平台通道读取）、刘海 `displayCutout`、`MediaQuery.displayFeatures`（铰链 / 折痕，`DisplayFeatureType.hinge / fold` 与 `state`）。键盘 inset 用于数字输入。
- 触摸起点落在 `systemGestureInsets.left / right` 以内或底部强制手势区以内：**该触摸不进入手势竞技场**（交给系统；避免与返回 / 首页手势冲突）。Android 允许应用声明排除区，每边至多 200 dp，底部不能排除：本应用**不声明排除区**，改为让所有控件内缩（窗口边距 = max(12, inset)；分类坞底距 = 底 inset + 8）。
- 窗口、读数、坞不得放入刘海 / 圆角区；照片本身可以延伸到系统栏之下（边到边），但适合放入时避开。
- 铰链 / 折痕（桌面姿态，E）：上半屏与下半屏分别是两个“可用区”；铰链条带（宽 = 铰链 bounds，至少 ±8 dp）内起落的**轻点**无效，跨越铰链的拖动不被打断；窗口与可操作控件不得落在铰链带内（4.14.3 的 16 / 40 起点）。展开 / 折叠切换时状态保持（4.15.14）。
- iOS（后续）：底部 Home 指示条的安全区按 `safeAreaInsets`；屏幕边缘系统手势（返回、控制中心）同理内缩；iPhone Duo 内屏横向的边缘手势区按真机测。

#### 4.15.16 延迟与交互渲染分级（对引擎的依赖，6.10 规定接口）

- **目标：预览在手指移动后的一个帧预算内更新**：触摸事件 → 像素上屏 ≤ 2 个 vsync（60 Hz ≈ 33 ms；120 Hz ≈ 17 ms）；其中渲染 ≤ 8 ms（N5 目标机型，【待验】）。不得超过 4.6.1 / 6.1 的硬上限 100 ms。
- **分级**：拖动中用 **T0 交互代理**（1–2 MP，约长边 1536 px，GPU，复用已解码的线性图像，参数以 uniform 方式更新）；松手后（或停顿 120 ms 无输入）精修到 **T1 视口分辨率**（≤ 300 ms 内换入，淡入 100 ms，不闪）；放大时 T1 只渲染视口 ROI；全分辨率 **T2** ≤ 1 s（沿用 6.1）。
- **降级**：T0 连续 3 帧超 12 ms → 长边降到 1024，再不行 768；恢复需连续 30 帧达标。**最新输入优先，不排队**：每帧只提交最新参数，上一帧未完成的渲染可丢弃。
- **指针事件**：每帧合并（Flutter 开启 `GestureBinding.resamplingEnabled`），用本帧的最后位置；速度用最近 60 ms 样本。
- **直方图**：从 T0 结果计算，≤ 15 Hz 更新；九格缩略预览只在窗口打开 / 松手刷新，不在拖动中刷新。
- **细节分类**（锐化、降噪、清晰度、纹理、颗粒）在低分辨率代理上看不出效果：拖动时用 **1:1 视口 ROI 渲染**（T0-ROI，视口尺寸、原生像素，要求同样 ≤ 8 ms 或降级为“松手后给 T1”并在读数下方提示“放大查看效果”）。【待验：引擎能否在 ROI 上满足预算】
- **一致性**：T0 与 T2 的颜色 / 色调须一致（排除噪点、锐化、颗粒）：目标平均 ΔE00 ≤ 1.0【待验】，否则松手时用户会看到“跳色”。
- 用户可见的唯一差异：T0 期间不可放大到像素级判断细节（读数下方不提示）。

#### 4.15.17 风格窗口的胶片分类（占位）

引擎正在增加**胶片模拟**。在风格窗口的“风格”分区之后预留一个“胶片”分区（行序：…明暗强度 · 胶片）：**【占位，参数待引擎确定】** 预期含：胶片（离散，色样条同风格）、胶片强度（1D）、胶片颗粒是否沿用“效果 · 颗粒”【开放】。与“风格”（色彩风格）是叠加还是互斥、是否进入“已调整”判定、是否写入 6.2 的逐张字段【开放】。在引擎提供之前，该行不显示；窗口行序与手势语法不变（离散 + 1D 即可套用）。

#### 4.15.18 待验与开放项（本节）

**待验**：增益曲线与 320 dp 基准；精细带阈值与倍数；轴锁 θ 区间；长按 380 ms 与双击 280 ms；吸附窗口与挣脱行程；弹簧 k / c；窗口宽 / 高与两窗并开的拇指可达性；N5 触感；惯用手自动推断的准确度与“自动”是否降为非默认；窗口避让位移；T0 分辨率与时间预算；ROI 细节渲染。

**开放**：①2D 参数的“离开”方式（现仅点窗换行）；②曲线 v2 自由点；③2D 精细化方案（现为“精细”开关）；④自动位在引擎给逐张建议值时是否也作为“复位目标”；⑤发布 / 分享迁入“更多”后的发现性；⑥是否在设置提供“灵敏度”（整体增益 ×0.7 / ×1 / ×1.4）；⑦浏览模式放大后单指平移是否保留（现保留）；⑧对比仅有长按手势，无按钮（决策 4），读屏用语义动作——是否还要在大屏键盘 / 外接设备提供快捷键（现为 Enter / 空格按住）。

## 6. 引擎需求（Engine requirements）

目标：以下每一项都必须与原型控件一一对应（键名、范围、默认值）。原型用 CSS filter 近似渲染，**视觉不是引擎行为的规范**；规范是本章的语义。现有 `EditParams`（`core/include/dapple/edit_params.h`）的差距在 6.9 列出。

### 6.1 处理流水线

输入：线性 ProPhoto 场景参考图（RAW）或显示参考图（JPEG）。顺序（沿用 `docs/architecture.md`）：白平衡/曝光 → 色调（log 域）→ 颜色（OKLab）→ 色域映射 → sRGB 编码 → 曲线 / LUT / 暗角 → 8 位输出。风格、明暗、调色盘、分级必须落在这条流水线上；自动处理 = 逐张明暗轻增强 + 默认风格。

**胶片模拟（可选，6.3 “胶片”组）：** 设置了 `film` 时，光谱胶片模拟（`docs/film/`）**替换**“色调 → 颜色 → 风格”三段：它以白平衡 / 曝光之后的线性 ProPhoto 为输入、输出显示 sRGB；之后曲线 / LUT / 暗角 / 裁切 / 细节阶段照常生效。`film_strength` < 100 时与普通流水线结果在显示域混合（两侧都已套用曲线 / LUT）。未设置 `film`（或库里没有该胶片）时输出与未集成前逐位一致。胶片库是随应用发布的 `core/data/film/dapple.dfp`（CC BY-SA 4.0，Andrea Volpato / spektrafilm；关于页必须署名，见 `docs/film/README.md`）。

实时性：拖动改值时预览反馈在**一个帧预算内**（目标 ≤ 2 个 vsync，硬上限 ≤ 100 ms，预览分辨率；见 6.10）；点开后全分辨率 ≤ 1 s；> 1 s 的操作显示进度（研究 E7）。会话保留已解码图像。（v0.5：“滑杆拖动”改指相对手势拖动。）

要求：
- 所有键缺省 = 默认值；JSON 往返无损（沿用 `toJson`/`fromJson`）。
- 参数应能被同步（4.8）按分类整组合并，且支持“相对默认的差异集”（`diff vs default`）。
- 渲染必须是确定性的：同一参数 = 同一输出，CPU 参考实现为真值，移动 GPU 着色器与之一致。

### 6.4 明暗（调性）

**输出（分析）：**

| 项 | 规格 |
|---|---|
| 最接近类别 | 9 类之一（key ∈ {高, 中, 低} × range ∈ {短, 中, 长}），含边际（距阈值 < 0.05 视为边界，策略参数在两类间插值） |
| 直方图 | 显示参考亮度（sRGB 伽马亮度）直方图，用于绘制面积图；曲线图背景同源；**随编辑实时更新**，并可对“原片”单独计算 |
| p5 / p50 / p95 | 同一亮度分布的分位点，位置 ∈ [0, 1]，用于直方图卡的三条虚线 |
| 区域条 | 11 条等宽（Zone 0–X，显示亮度域），仅 UI 绘制，无需引擎输出 |

分类起点（研究笔记，**全部为未验证的设计提案**，需在用户相册上调参）【待验】：
- 亮度计算：显示参考亮度，降采样到约 512 px，可中心加权 60/40；
- 基调（key）按 p50：< 0.28 → 低，0.28–0.65 → 中，> 0.65 → 高（辅以 μ）；
- 跨度（range）按 S = p95 − p5：< 0.35 → 短，0.35–0.65 → 中，> 0.65 → 长。

**输入（处理）：** `toneTarget`（9 类之一或空 = 最接近类别）+ `toneStrength`（0…100）。
- 规则：**保持类别，只修技术缺陷**（剪切、偏色、噪点），把 p50 推向目标类的中心，不推向 18% 灰。不猜意图、不判断“拍坏了”。
- 目标 = 最接近类别时仍应用轻微增强（强度随 `toneStrength`）。
- 目标 ≠ 最接近类别时，向目标类别按 `0.35 + 0.65 × 强度` 的比例逼近（原型的预览近似：亮度因子 高 1.2 / 中 1.0 / 低 0.78；对比因子 短 0.8 / 中 1.0 / 长 1.24；先取目标 / 当前比值，再按该比例做指数插值）。真实实现按研究给出的各类 p50 / 跨度目标【待验】。
- 引擎必须能为**同一张照片同时渲染 9 个目标类的预览**（每格预览强度 = max(0.6, `toneStrength`)），延迟满足 UI 同屏更新（缩略图分辨率）。

自动处理：
- 到达后自动 = 逐张明暗轻增强（强度 = 默认明暗强度）+ 默认风格。
- 现有 `AutoAdjust`（中位亮度驱动曝光、高光 / 阴影保护、偏色校正）需要改为“类别感知”：先分类，再按 6.4 规则增强。【开放：两种自动策略的合并】

### 6.6 调色盘

二维控件 `palette {x, y}`，x、y ∈ [0.04, 0.96]，叠加在风格之上，受 `lookStrength` 缩放：

| 轴 | 语义 | 原型的预览近似（强度 s=lookStrength/100） |
|---|---|---|
| x | 左淡 → 右浓（色彩浓度） | 饱和度 × (1 + (x − 0.5) × 0.9 × s) |
| y | 上暖 → 下冷（冷暖倾向） | w = (y − 0.5) × s；w < 0 偏暖（加暖色，系数 0.55）；w > 0 偏冷（色相向冷偏移，系数 26°） |

- 风格切换时 `palette` 重置为该风格默认点；“回到默认”清除覆盖。
- 无数值显示；aria 文本由 UI 从 x、y 计算（4.7）。
- 实际映射（色度增益范围、冷暖偏移的量纲）由引擎定义【开放】；必须在 `lookStrength = 0` 时无任何作用。

### 6.7 HDR / 全景 / 实况

#### 输入：有序来源列表（时间升序）、基准帧、参数。输出：新的合成结果项（可编辑、可发布）。通用要求：阶段 + 进度、可取消、可后台、失败返回类型。

| 任务 | 参数（键、取值、默认） | 输出 | 失败 |
|---|---|---|---|
| HDR 合并 | `hdrDeghost` ∈ {off, low, mid, high}，默认 mid；`hdrAlign` 布尔，默认 true；`hdrBase` ∈ 来源，默认中间帧；来源 ≥ 2 | 线性浮点图像（可继续在 Dapple 流水线中编辑），kind=HDR | 对齐失败 → “没能对齐这几张”，可换基准帧重试 |
| 全景拼接 | `panoProj` ∈ {sph, cyl, persp}，默认 cyl；`panoWarp` 0…100，默认 0；`panoCrop` 布尔，默认 true；`panoFill` 布尔，默认 false；基准帧；来源 ≥ 2 | 线性浮点图像，kind=全景 | 同上 |
| 视频转实况 / 动态 | 片段起点（视频内位置，窗口固定 3.0 s）；封面时间（窗口内）；`liveStab` 布尔，默认 true；`liveMute` 布尔，默认 true | iOS：实况照片（静帧 + 配对视频，同一内容标识）；Android：动态照片（JPEG/HEIC + MP4，Google Motion Photo XMP） | 【开放】 |

- 进度回调：阶段 ∈ {对齐, 合并, 处理}（分别占 0–33 / 34–67 / 68–100 %）、百分比 0…100。取消须在 1 s 内生效。
- 自动识别：给定一批已处理照片，返回分组（包围曝光 / 全景序列）及其时间、EV；未验证【待验】。
- 第三方库的许可：避免 GPL（LuminanceHDR、Hugin 等）；OpenCV（Apache-2.0）可用；DNG SDK 的许可需核对【待验】；FFmpeg 已定为 LGPL 动态链接，只编译所需解码器，并始终跟进最新修复版（见 `docs/legal/ffmpeg-lgpl.md`）。
- 性能：3–5 张 6000 万像素帧的内存与时间未测【待验】。

### 6.8 渲染与导出

| 项 | 规格 |

### 6.10 交互渲染分级（v0.5，支撑 4.15.16）

编辑器的相对手势要求预览“跟手”。引擎必须提供：

| 项 | 要求 |
|---|---|
| 分级渲染 | **T0 交互代理**：1–2 MP（长边约 1536，可降到 1024 / 768）、GPU、复用已解码线性图像、参数以 uniform 更新，单次 ≤ 8 ms（目标机型 N5，【待验】）；**T1 视口**：松手或停顿 120 ms 后，视口分辨率（放大时仅视口 ROI），≤ 300 ms；**T2 全分辨率**：≤ 1 s（沿用 6.1） |
| 调度 | 每帧只接收最新参数集；未完成的旧渲染可取消；不排队；T0 与 T1 / T2 可并行但新输入总是抢占 |
| 一致性 | T0 与 T2 在颜色 / 色调上一致（平均 ΔE00 ≤ 1.0，不含噪点 / 锐化 / 颗粒）【待验】 |
| ROI 细节渲染 | 锐化、降噪、清晰度、纹理、颗粒需在**原生像素的视口 ROI** 上渲染才可评判；拖动这些参数时请求 T0-ROI（视口尺寸、1:1），若超预算则降级为松手后 T1 |
| 直方图 | 由 T0 结果计算，≤ 15 Hz；支持原片直方图（对比时） |
| 缩略预览 | 九格目标预览（6.4）在窗口打开 / 松手时一次性渲染，拖动中不要求 |
| 自动位 | 引擎应能返回每个参数对该张照片的“自动位”（若无逐张建议值 = 默认值）【待验】，供读数标记与复位目标使用 |
| 原片 | 长按对比要求原片渲染立即可得（沿用 6.8；应缓存） |

## 7. 无障碍与交互约束（需求级）

详见指南第 12 节。需求级要点：

- 点击区 ≥ 44 pt（iOS）/ 48 dp（Android）。【缺陷：原型有 36 高的按钮（连接卡动作、“选择”胶囊）和 40 高的分段 / 大屏按钮，须加大命中区】
- 所有状态不只靠颜色。
- 所有自定义手势有等价操作：长按多选 ↔ “选择”；片段条拖动 ↔ 方向键；**编辑器（v0.5，4.15.11）**：参数相对拖动 ↔ 每个参数行的可调整语义节点（增大 / 减小 / 大步 / 复位 / 输入数值）；2D 控件拖动 ↔ 子节点增减；长按原片 ↔ 照片节点的语义动作（负责人决定界面上不放对比按钮）；窗口拖动 ↔ 语义动作“移到左 / 右 / 下”。（原“按住对比 ↔ 对比开关”“抓手”“调色盘 ↔ 方向键”条目作废。）
- 动效尊重“减少动态效果”。
- 屏幕阅读器：直方图、调色盘、滑杆、进度条、选中序号均有文本。

## 8. 开放项与待验清单（汇总）

**设备与布局【待验】**
1. Find N5 内屏 / 外屏的真实 dp 宽度与 devicePixelRatio（原型 840×760 / 412×945 为假设；官方只给像素：内屏 2480×2248，外屏 2616×1140）。
2. iPhone Duo 的 pt 尺寸：苹果只公布像素与 ppi（内屏 1878×2670 @430 ppi；外屏 1398×2034 @460 ppi），原型按 3x 换算为 626×890 / 466×678，安全区 50/30 为假设。

**相机传输【待验】**
7. A7R V / X-T50 在 RAW+JPEG 下的传输稳定性；先传预览再补 RAW 的可行性；前台服务类型与 Play 审核；Android 16 本地网络权限。

**算法【待验】**

**交互【待验】**

## 9. 原型内部矛盾（汇总）

1. Main 与 Large 的颜色 token 值不同（指南 2.3 逐项列出）；规定以 Main 为准。
2. 双向滑杆刻度与填充：Main 在默认值，Large 固定在中点且始终从 0 填充。
3. 九宫格格内标签：Main 只写专业名，Large 写白话 + 专业名。
4. 直方图：Large 的“更接近”前缀；标签姿态下不固定在顶部。
5. 同步设置：Main 选目标缩略图（且缩略图行被渲染 4 次），Large 直接同步到全部。
6. 平台预设与导出尺寸：Main 6 个、尺寸 1440/2048/2560/3840；Large 4 个、尺寸 原尺寸/4096/2560。
7. 裁切旋转按钮：Main“旋转 90°”，Large“向左旋转 / 向右旋转”。
8. 调色盘 aria 与范围：Main 偏暖 / 偏浓 −100…100；Large 浓淡 / 冷暖 0…100。
9. 实况窗口 22% × 14 s = 3.08 s，与“3.0 秒”文案不一致；“0:14”写死。
10. 撤销栈全局共享。
11. 字号：Large 使用 14 / 20 / 24 / 30，超出指南字号阶梯（11/12/13/15/17/22/28/34）。
12. 控件高度：Large 的 Android 控件 40（低于 48 dp）；Main 的连接卡按钮与“选择”胶囊 36。
13. 已处理标记：Main 转圈 + 蓝点，Large 圆环 + 白点。
14. 暗色 `danger` `#D8453F` 上白字对比 4.34:1，低于 4.5:1。
